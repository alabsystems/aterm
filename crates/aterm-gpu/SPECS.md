## 0. Notation used in the statements

Paths are relative to `crates/aterm-gpu`. Gap numbers are the rows of §7 of
`AUDIT-trust-for-test-migration-2026-10-15.md` (historical internal audit).

- `S`: a renderer configuration (theme, px, text blending, shaping config, selection_fg/inactive, cursor blink phase, cursor style override, pad). A pair (`cpu: aterm_render::Renderer`, `gpu: GpuRenderer`) is built under the same `S`. *Settled* means `debug_block_on_lazy_fallbacks` has been called (`common::font_settled`).
- `I`: an `aterm_render::RenderInput` (`Terminal::cell_frame` plus any effect channels: nova_add, rain, glow_under, cursor_glow_add, glow_halo, fire_patch, fire_halo, char_fg, cursor_trail, ink, word_decorations, images, selection_*).
- `Adm`: the inputs reachable from `Terminal::new(r,c)` for r, c <= 4096 through any byte stream, plus effect channels that satisfy their `RenderInput` invariants (sorted unique ink and so on).
- `Frame`: (width, height, pixels as `0xTTRRGGBB` with TT = 255 - alpha). `C(I)` = `cpu.render_input(I)`. `G(I)` = `gpu.render_input(&mut WindowGpu::new(), I, None)` on a fresh `GpuRenderer`. `GpuW` / `GpuM` = the same frame through the wgpu arm / the armed Metal arm (`arm_metal_for_test`). For comparisons with `C`, bloom is off and shimmer is off or phase-pinned.
- `dmax(a,b)`: the largest per-channel |a - b| over all pixels (`common::max_channel_delta`). `Exc(a,b,t)`: the number of pixels with dmax > t (`common::count_exceeding`).
- `E`, the exactness domain: pixels with hard 0/255 coverage (procedural blocks, box drawing, shades, solid fills, opaque cursor and trail quads, bands, chrome raster runs), plus additive/source-over effect light over glyph-free ground on the native plain-Unorm offscreen (`GpuRenderer::additive_is_byte_exact`).
- `Fresh(I)`: `G(I)` on a new window (full repaint, no cache). `Seq(h, I)`: the frames one `GpuRenderer`, with one or more interleaved `WindowGpu`, returns through `render_input_cached` / `present_input_readback` / `present_to_view` after history `h`.
- Path counters: `scissor_taken` (Sc), `full_repaints` (Fu), `scroll_rescues` (Rs), `gate_hits`/`gate_misses`, `last_instances`, `metal_encode_band_shifts`, `metal_encode_inline_waits`.
- `Harvest_A(seq)` / `Harvest_B(seq)`: the `VideoTake` from the copyable-swapchain stand-in arm (`present_swapchain_standin_for_test` + video tap) and from the headless virtual arm (`present_virtual` + video tap), each on a fresh `WindowGpu` after `reset_glow_ease_for_test`.
- `maxTex`: the device's `max_texture_dimension_2d` (Metal arm: 16384). `clampD(d)` = min(max(d,1), maxTex).
- `ImgOrder(cell)`: the cell's image layers ordered by z, ties by placement order, split into tiers by `KITTY_IMAGE_BELOW_BG_Z_THRESHOLD` (T = i32::MIN/2): deepest (z < T), under-text (T <= z < 0), over-text (z >= 0).
- `Latch` = `metal::loss::LossLatch`. For a `ty_model!` / `aterm_spec::derive` machine M: `Enabled_M(a, s)`, `Succ_M(a, s)`, `Inv_M(name, s)`; `proj(v)` is the projection of a Rust value onto M's state that the conformance test builds.
- `MSL(L)` / `WGSL(L)`: the shader source text compiled for `ShaderLibrary` L.
- **GPU semantics.** A statement about bytes that Metal or wgpu execution produces needs a model of the GPU (rasterizer, blend, sampler, sRGB encode, copy engine). Neither Trust nor Clean has one, and the audit's gap table has no row for it. Such specs list gap 8 (FFI/platform assumption channel) and stay unprovable until a GPU execution model is written as a PlatformSpec (§5.1).
- **Owner.** Specs marked `owner` other than aterm-gpu are properties of `aterm-render`, `aterm-core` or `aterm-effects` that these GPU tests merely sample. They belong in that crate's `SPECS.md`; the GPU side is then `gpu-frame-refines-cpu` citing them (gap 12).

## 5. Implied specs that look wrong, or disagree with the code

1. **No GPU execution model exists.** Every spec about bytes the GPU writes (refines-cpu, metal == wgpu, pass
   semantics, blit, crown, shader kernels, tray, bloom, frame cycle) needs a model of the rasterizer, blend,
   sampler, sRGB encode and copy engine. The audit's gap table has no row for it; these specs list gap 8, but
   closing gap 8 as written (platform host pass, PlatformSpec) is not enough. A new audit row is needed. The
   cheaper route for `gpu-frame-refines-cpu` and `metal-arm-byte-equals-wgpu-arm` is plan equality: prove that
   both backends (and the CPU) lower one frame plan to the same instance streams and pass list, and keep the
   shader-to-pixel step as one named assumption.
2. **`present_glass::classify` and `secs_to_ns` can panic.** `Duration::from_secs_f64` panics when the span
   overflows `Duration` (about 1.8e19 s), so a garbage `presentedTime` crashes the present handler. A no-panic
   spec fails until the span is clamped; `glass-sample-classify` carries the precondition meanwhile.
3. **The present-tag successor ring can lie.** `deliver_report` reads the successor from a 16-slot ring; with
   16 or more registrations after `serial` before its handler fires, the slot is overwritten and the successor
   is a later present's tag. `a_report_names_the_next_registration_as_its_successor` covers at most 2 later
   registrations and asserts the successor only `if ours` (another test may own the process-wide sink), so its
   coverage depends on test order.
4. **`scaled_border_px` overflows.** `base * u32::from(scale_q4)` overflows u32 for base > u32::MAX/255
   (debug panic, release wrap). It needs a stated precondition or a saturating multiply.
5. **`VideoTap::should_capture` divides by fps.** `1_000_000 / fps` is a division by zero for
   `fps_cap = Some(0)`, and `t + interval` can overflow. Production constructors clamp fps to 1..=120 but
   `test_tap` bypasses the clamp: a type-invariant obligation, not a live bug.
6. **Tautologies and unobserved claims.**
   - `renderer::sdr_glow_attack_is_owned_per_window`: per-window ownership is guaranteed by `&mut self` on
     `WindowGpu` fields (no statics); only the attack/reset envelope carries content.
   - `present_real::production_present_resolves_odd_bands_and_trailing_content` computes the conformance
     projection `covered = if full_surface_matches {5} else {4}` after `assert!(full_surface_matches)` passed,
     so the model comparison is decided by an earlier assertion and the negative control exercises only the
     `ty_model`, not the code. It is not a real gap-10 refinement binding.
7. **Three tolerance bounds for one property.** `parity_fuzz` and `parity_fuzz_adversarial` accept dmax <= 40
   on up to 8 fringe pixels, the example parity tests assert dmax <= 8 everywhere, and rain asserts <= 2.
   `gpu-frame-refines-cpu` needs one tolerance table derived from the sRGB-encode rounding argument, not
   empirical ceilings ("Metal measures 1").
8. **A known CPU != GPU divergence is carved out, not fixed.** `parity_fuzz_adversarial` skips DECDHL frames
   because GPU UV plus NEAREST sampling picks a different source row than the CPU's integer clip when the top
   half is anchored above the view. `gpu-frame-refines-cpu` carries the same carve-out until it is fixed.
9. **Tests that could pass while checking nothing (fixed).** No GPU, no font, or a downlevel adapter now
   ends a test COULD NOT RUN, never a pass: a parity test runs every other check, then ends COULD NOT RUN
   naming the byte-exact comparisons the adapter could not make (`tests/common`'s `ByteExact`). The two
   `merged_ligature_parity` tests use the checked-in LuckiestGuy face. Still open:
   `nova_parity::supernova_detonation_peak_over_text_matches_within_tolerance` ends COULD NOT RUN before its
   <= 8 check on a downlevel adapter, though only the byte-exact claim depends on it.
10. **A reach floor instead of the rule.** `scroll_blit_gpu` uses reach floors (rescued >= 14, >= 8; "some
    notches legitimately refuse") without pinning which notches refuse; the spec should state exactly when
    `scroll_blit_plan` returns Some.
11. **Source scans stood in for path contracts (removed).** No test reads Rust source now. The atlas scan
    became `GpuRenderer::raster_changed`, the one door that drops the CPU glyphs and the GPU atlas together.
    The `hdr_gate.rs` scans became construction and a driven test: `LiveSurface` has no bare configure;
    `metal_attach_format` reads the screen and picks in one function; `hdr_screen_upgrade_decision` reads it
    only past the cheap gates (a counting reader checks it); and
    `the_screen_upgrade_moves_the_layer_before_it_promotes_the_metadata` drives the monitor-change order on a
    real Metal swapchain, with the misordered `want` and the missing revert as negative controls. Not driven
    on a host this suite runs: the Windows `reconcile_live_hdr_state_if_due` publishing the upgrade only under
    `if surf.is_hdr()`, the present calling that reconcile once before acquisition, and the in-flight-acquire
    leg of the Metal flip (deterministic only with a held acquisition). Those stay path contracts (gap 4).
12. **A prose pin inside a spec test.** `loss::the_latch_flips_only_on_lost_and_stays_flipped` pins the
    `Debug` text of `CbOutcome` ("PageFault"). Drop that line when the spec lands.
13. **Stale comments.** `selection_highlight.rs` says selected cells keep their "glyph foreground unchanged",
    but the policy is `floor_selection_fg` contrast. `ligature_parity::ligature_font_gpu_matches_cpu` names
    the row `a => b != c == d -> e <= f` but processes `a => b != c == d -> e`.
14. **Wrong crate.** The specs marked with another owner in §1 belong to that owner, with their tests.

15. **Claims that hold only on a sample.** `selection_highlight::inactive_selection_bg_gpu_matches_cpu` asserts
    the inactive selection bg "must visibly differ" from the active one; `derive_inactive_selection_bg(a, bg)` =
    `blend(bg, a, 128)` equals `a` when `a == bg`, so the general spec needs that precondition.
    `oversized_resize::oversized_grid_clamps_offscreen_instead_of_aborting` is vacuous in its `w_a == w_b` half
    when `cw <= 12` (both column counts clamp to 4096); only the strict-clamp branch carries content.
    `scissor_repaint::bloom_scissor_dirty_band_stays_proportional` asserts a ratio (`scissored*4 < full`) that
    stands in for the per-dirty-row bound of instance-stream-confined.
16. **A duplicated implementation.** `renderer::scaled_border_px` is a verbatim copy of the aterm-gui CPU twin
    ("the two must never drift"), and `drop_border_px_gpu` carries the same "MUST stay in sync" comment with no
    check at all. Make each one shared function; the spec is then one contract, not an equivalence.
17. ~~**A hand-written TLA model.**~~ Fixed: GpuEncode is `aterm_models_render::gpu_encode_model`
    (`ty_model!`), and `tests/conformance_gpuencode.rs` runs in the default suite on the interpreter, with a
    negative control the model's mutant admits.
18. **A mislabelled field.** `present_real::one_shot_presented_snapshot_is_independent_from_video` asserts
    `snapshot.t_us == 77`, the integer passed to `presented_snapshot_after_present`, while the harness passes
    frame ordinals to `video_after_present`. Either the parameter is a timestamp and the tests pass ordinals,
    or `t_us` is misnamed.

## 6. Proof order (easiest high-value first)

1. **`should-slice-nonempty`**: the only spec blocked by gap 0 alone. One `usize` comparison, already bound
   to the GpuEncode model; prove it the day a Clean-publishing seal lands, and it retires the GpuEncode
   conformance test.
2. **Gap-1/3 deciders**, each straight-line or a small `match`, decidable by evaluation or `omega`:
   `surface-attach-fallback`, `swapchain-config-validate`, `scaled-border-px` (with its precondition, §5.4),
   `band-shift-ops`, `present-copy-rect-union`, `present-crop-normalize`, `startup-probe-slot-encoding`,
   `frame-latency-policy`, `blit-uniform-layout`, `capture-encoding-validity`, `dense-enum-tables`,
   `loss-classify-table`. Together they retire about 20 tests and force the enum/struct carriers (gap 1)
   that everything after them needs.
3. **`hdr-gate-policy`** (5 tests, an exhaustive bool/Option<f32> policy) then `hdr-reconfigure-retag-refinement`
   and `acquire-worker-guards-refine-model` / `capture-lifecycle-refinement` (gap 10 refinements over
   const fns): small state, high value, they bind existing `ty_model!` machines to the code.
4. **`fb-dim-clamp`, `visible-source-scissor`, `frame-pass-coalescing`, `frame-plan-draw-order`,
   `effect-pipeline-demand` (demand half)**: the pure planning layer under the GPU encode. With
   `repaint-path-selection`, `dirty-gate` and aterm-render's `compute_dirty_rows` soundness lemma, this is the
   pure core of `cached-render-equals-fresh` (40 tests).
5. **`pixel-conversion-laws`** (10 tests; loops and floats) and `loss-latch-sticky-first-reason` →
   `encode-session-loss-protocol` once `&self` views (gap 2) and atomics land.
6. Everything with gap 8 waits for the platform lane and a GPU execution model (§5.1); start with plan
   equality for `gpu-frame-refines-cpu`, the largest collapse in the crate.

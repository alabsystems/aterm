# THE PIPELINE TABLE, as text — the golden `crate::pipeline_table::tests::
# the_pipeline_table_is_what_it_says` pins.
#
# One line per render pipeline aterm builds, in `Pipeline` order, with every
# field that decides a pixel: the shader library, both entry points, the
# colour-target ROLE, the blend equation for the RGB and alpha halves, the write
# mask, the vertex layout and the topology.
#
# The table itself (crates/aterm-gpu/src/pipeline_table.rs) is what BOTH backends
# build from — `renderer.rs` for wgpu, `metal/pipelines.rs` for Metal — so this
# file produces no behaviour. It exists so that changing any of the state above
# is a diff a reviewer sees in a second file, rather than one character inside a
# 40-line descriptor. If a change here is intended, the table changed first.
#
# `blend=none` is REPLACE-by-omission (`blend: None` in wgpu, blending disabled
# in Metal); `rgb(One Zero Add) a(One Zero Add)` is the same fixed-function state
# spelled as `wgpu::BlendState::REPLACE`.
#
# `load=` is the row's pass load-op convention (`PassLoad`): `Clear`/`Load`
# where every production pass the row draws in opens the same way (blit /
# bloom / shimmer / tray), `dyn` where the frame plan or another row's pass
# decides. Declarative metadata for W4's encoder port; nothing consumes it yet.
#
# `binds=` is the row's Metal binding map (`BindSpec`): `vu` the vertex-stage
# uniform `[[buffer(n)]]` slot, `ft`/`fsamp`/`fb` the fragment-stage
# `[[texture]]`/`[[sampler]]`/`[[buffer]]` slots, `-` for none. The MSL scan in
# `metal::shaders` holds these equal to the `.metal` declarations both ways;
# the instance stream is not listed because it always binds at
# `INSTANCE_STREAM_SLOT` through the vertex descriptor.

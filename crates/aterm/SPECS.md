Most of this crate's tests are live-headless lanes. They boot a real instance and read it over its
control socket. Their specs are stated at the level of what a client can observe (`Obs`), and they
cannot be proved until gap 8 (effects) and gap 13 (threads) close. The plan's route ("Order of
work") is to factor out the pure decider (classifier, policy, ledger, admission model) and prove
that. The live lane stays as the effectful shell's conformance check (gap 10) until the platform
lane exists. Several of these deciders live in other crates (`aterm-agent`, `aterm-gui`,
`aterm-cli`, `aterm-control`, `atpkg`), so their proofs belong in those crates' `SPECS.md`. The
aterm test is deleted once that proof and the shell's conformance check both exist.

## 0. Notation used in the statements

- Test paths in §1 are `<file stem>::<test>`: `main::…` is `crates/aterm/src/main.rs`,
  `compiler_probe::…` is `crates/aterm/src/compiler_probe.rs`, `live_ctl::…` is
  `crates/aterm/tests/support/live_ctl.rs`, and every other stem is `crates/aterm/tests/<stem>.rs`.
  §2 gives every repo-relative path.
- `Lossy(a)` = `a.to_string_lossy()` on an `OsString`.
- `B(rest)` = `payload_boundary(rest)`: the first index i with `Lossy(rest[i])` ∈
  {`-e`, `--command`, `--`}, else `|rest|`. `Pre(rest)` = `rest[..B(rest)]`.
- `WindowFlag` = {`--window`, `--headless`, `--diagnose`}.
- `Field(vv,k)`: the trimmed suffix of the **first** line of `vv` that starts with `k`, kept only if
  it is non-empty. `find_map` stops at the first prefixed line, so an empty first `commit-hash:`
  hides a later one.
- `TrustEvidence(vv)`: some line l of vv has `l.strip_prefix("binary:")` trimmed = `trustc`, or
  `l.strip_prefix("trust:")` with a non-empty trimmed rest; or the first line contains `(trustc)` or
  `(trustc `.
- `Env'`: the process environment after the call (through `aterm_log::env` set/unset).
- `UpToDate(line)` ⇔ the line contains `is up to date`.
- `Obs(inst)`: what a client can observe of a live headless instance: control-socket replies, the
  `EVENT` stream, `timeline`, the fake worker's key and submit logs, files under its scratch roots,
  its exit status and its process table. Every live spec is a refinement at the `Obs` level.
- `Classify(rows, program)`: the agent-verdict reader in `aterm-agent`/`aterm-gui`, applied to the
  last 40 **drawn** rows of the session grid. Its range is {`-`, `idle`, `busy`, `prompt`,
  `unknown`, `wall:<kind>`}.
- `Decide(screen, cfg, session_meta, history)`: `aterm_agent::supervise`'s approval, question and
  turn-end policy. Its value is a sequence of key/text actions, or `Escalate`.
- The `blocking_gaps` column lists gap numbers from §7 of
  `AUDIT-trust-for-test-migration-2026-10-15.md` (historical internal audit).
  Gap 0 (an installed seal that publishes Lean-discharged rows) blocks every row and is not repeated
  in the column. No spec here is blocked by gap 0 alone.

## 5. Implied specs that look wrong, or disagree with the code

1. **`session-lane-effect-order` has no sample.** It is a property of `main`'s control flow (an
   effect after a gate, a confirmation after the shell spoke, no timer on it), and a scan of
   `main`'s source text cannot hold one: text order is not call order, a rename or reformat
   breaks the scan, and a wrong reorder inside a callee passes it. It stands as the trace spec
   over the CFG; the single `aterm_gui::main_entry` call site of the Windows image is the same
   kind of rule, for an aterm-census guard.
2. **`main::a_spawn_is_handed_to_the_sibling_as_new_window_never_as_a_plain_launch` repeats one
   point.** It asserts `alias_route("aterm-gui","new-window") == AliasWindowVerb` inside the
   8-iteration loop, a constant that never depends on the loop variables. It never feeds the
   produced argv to `alias_route`, which is what its doc's "cannot route it a second time" needs.
   `spawn-handoff-round-trip` (b, c) states it.
3. **`host_live::the_host_hands_over_what_it_cannot_prove_and_types_nothing`'s doc misnames the
   default.** It opens "Under the owner's approve = \"safe\" (full power, the default, answers these
   boxes…)", which reads as if safe were the default full power. The default answers every box
   (`the_host_answers_every_box_by_default`). `safe` is the limit that hands this box over.
4. **`nests_inside_aterm` is compiled `#[cfg(any(windows, test))]`.** Off Windows it has no
   production caller, so its table test runs test-only code on the mac/linux gate. The spec still
   holds for the Windows production caller, so prove it with the Windows cfg.

## 6. Proof order (easiest high-value first)

No spec is blocked by gap 0 alone, so the order prefers the fewest and smallest gaps, then tests
retired, then how many other specs reuse the lemma.

1. **`nests-inside-aterm`** (gap 3 only). Four bools; it fits the scalar lane once `&&` branches
   are admitted. Low value alone, but it is the cheapest end-to-end exercise of the pipeline for
   this crate.
2. **`windowed-sibling-staleness`** and **`trustc-parenthetical`** (gaps 1, 3). Straight-line code
   over `SystemTime`/`Duration` and one `split_once`. Each retires a test and is a lemma of a larger
   spec (`trustc-parenthetical` feeds `rustc-vv-parse`).
3. **`strip-flags-payload-boundary`** (gaps 1, 3, 5, 7). One filter over `&[OsString]` with a
   boundary index. It is the lemma that `take-no-reroute`, `plain-launch-request` and
   `update-successor-stays-window` build on, so it unblocks the front-door routing family.
4. **`detect-flavor-characterization`** with **`rustc-vv-parse`** (gaps 1, 3, 5, 7). Line iterators
   with `strip_prefix`. Together they retire all 11 `compiler_probe` tests and make
   `build-stamp-domain` a short composition.
5. **`front-door-forward-lines`** and **`alias-route-table`** (gaps 1, 3, 5, plus 12 for the
   cross-crate `Verb`). Formatting and `&str` matches. They sample 7 `main` tests and retire 5 of them, and `alias-route-table`
   is the target half of `spawn-handoff-round-trip`.
6. **`is-windowish`**, **`window-host-for`**, then **`update-verb-lines`**. Same carriers as above.
7. The live family through its pure deciders, in their home crates: `worker-phase-classifier`
   and `Classify` (aterm-agent) retire the agent-verdict lane's logic; `Decide`'s approval,
   question and turn-end arms (aterm-agent) retire the logic of 28 `host_live` and
   `supervise_turn_end` tests; the resize ledger and undo (aterm-gui, aterm-grid) retire 13
   `render_desync` tests. Each live test is deleted only when its decider is proved and the shell's
   conformance check (gap 10) exists.

## 0. Notation used in the statements

Paths are relative to `crates/aterm-update-core`; function names are `module::item`. `++` is concatenation,
`<=>` is iff, `|x|` is length, `a ⊖ b` is saturating subtraction, `dec(n)` is the decimal spelling of `n`, and
`trim` is `str::trim`. On `Option`, `max` orders `None` below every `Some`.

- `Safe(s)` := `cdn::path_segment_safe(s)` := `s != ""` && `s != "."` && `s != ".."` && every byte of `s` is in `[A-Za-z0-9._-]`.
- `API(u)` := `cdn::is_api_host(u)` := `"https://api.github.com/"` is a prefix of `u`.
- `Canon(c)` (a tag component) := `c` is non-empty ASCII digits && (`|c| = 1` || `c[0] != '0'`). `dec(c)` is then its value in Z.
- `Code(s)` := `http::curl_http_error_code(s)`. Let `i` be the first index of `"returned error: "` in `s`, and `D` the longest ASCII-digit prefix after it. `Code(s) = Some(dec D)` iff `D != ""` and `dec D <= 65535`; it is `None` otherwise, including when the marker is missing.
- `Block(h, name)`: the lines of `h` (`str::lines`) after the LAST line that starts with `"HTTP/"` (all lines when there is none), restricted to lines with a `:` whose key (the text before the first `:`), trimmed, equals `name` ignoring ASCII case. `V(h, name)` is that sequence of trimmed values.
- `Opts(L)` is the option list a lane passes to `curl_argv` (everything before the `-q`/User-Agent/`--`/url framing). "Flag `f` has value `v` in `L`" means `L[i] = f` and `L[i+1] = v` for the unique `i` with `L[i] = f`. Statements about option lists hold for every caller value (cap, dest, body, headers, timeout) that is not itself one of the named flag words.
- Handoff policy: `P` ranges over `HandoffPolicy`. `R(P)` = `P.applies_to_producers`, `cc(P)` = `P.carry_ceiling()`, `rx(P)` = `P.relaxes_land_gate()`, `asks(P)` = `P.asks_anything()`. `Comb(Ps, r)` = `HandoffPolicy::combined(Ps, r)` = {range: `Some(r)`, carry: max over `Ps` of carry (None lowest), gate: Relaxed if any is Relaxed, else Strict if any is Strict, else None}. `Hull(rs)` = `PolicyFile::hull(rs)`. `FB(f, b)` = `PolicyFile::for_build(f, b)`.
- Sentinel: `Sigma(path)` in `Option<(build: u64, attempts: u32, names: Vec<LaunchName>)>` is `read_record`'s parse of the file. The first whitespace token is a u64, the second (default `"0"`) a u32, and every later token `pid:secs:micros` that parses becomes a name. An unreadable, non-UTF-8 or unparseable file gives `None`. `last32(N)` keeps the last 32 names.
- pkg_check: `S` is a `Stamps`. `elapsed(t, n, p)` := `(n ⊖ t) >= p || (n ⊖ t) < -p` (signed, saturating). `remaining(t, n, p)` := `0` if `elapsed(t, n, p)`, else `min(max(0, t + p - n), p)`. `I` = `FULL_PASS_INTERVAL_SECS` = 21600 and `Sp` = `PASS_SPACING_SECS` = 300.
- Roster: `U(s)` = `aterm_types::rfc3339::parse_utc(s)` (exactly `YYYY-MM-DDTHH:MM:SSZ`, 20 bytes). `Ed(k, m, sig)` is ring's Ed25519 verify of `sig` over `m` under the 32 raw bytes that `aterm_codec::base64::decode_strict(k)` gives; Ed25519 unforgeability is an axiom. `Usable(k)` := `k != ""` && `decode_strict(k)` is Ok with length 32.
- Effectful specs (fs, process, lock) are stated over an abstract file-system and process state. They stay specs because they are general contracts, and they are blocked on gap 8. Several of the functions they name carry `#[cfg_attr(trust_verify, trust::skip)]` today, so proving them includes removing the skip; the pure core of each should be factored out and proved first (plan, order of work step 4).

## 5. Implied specs that look wrong, or disagree with the code

1. **The code and its doc disagree**
   - `src/pointer.rs::parse_location`: the doc says every other Location is Refused. But when owner/repo/name
     is not a safe segment and `accept_tag(tag)` is false, the function returns `OtherTag` before it checks the
     source. The order disagrees with the doc. It does no harm, because `latest_download_url` already refuses an
     unsafe source. `pointer-location-strict` states the code's order. Fix the doc, or move the source check first.
   - `src/tag.rs::parse_release_tag`: the `TagError::Overflow` doc says "canonically spelled, but a component does
     not fit". Yet the first overflowing component wins even when the tag has more than three components
     (`v1.2.3.99999999999999999999` gives Overflow, though the doc's rule makes it Malformed). `release-tag-grammar`
     states the code. Decide which one is intended; no test samples this case.
2. **Properties that hold only under a precondition the tests never break**
   - `http::classify_asset_failure` with `download_error_is_rate_limit`: the web-host 403/404 message embeds the
     raw url, and `download_error_is_rate_limit` is a substring test. A url that contains `rate limited (HTTP `
     would make a blocked-host 403 read as a rate limit. `asset-failure-classification` carries "url does not
     contain the marker" as a precondition. A typed error would remove the precondition.
   - `src/http.rs::a_vendor_get_attempt_answers_body_not_modified_or_the_status` asserts that the `VendorStatus`
     text does not contain `GitHub`. The Display embeds the url verbatim, so this holds only because the sampled
     url has no `GitHub` in it. It pins wording, not a property; `http-error-display` replaces it.
3. **Mislabelled or incomplete samples**
   - `src/sentinel.rs::a_launch_the_killer_forgives_is_not_a_crash`: the comment at lines 375-376 says "but a
     candidate that DIED keeps its count". The code after it observes a launch and then forgives it (it asserts
     1, then 0). The died-candidate case it names is never sampled. `boot-sentinel-state-machine` covers it.
   - `src/manifest.rs::absent_optionals_are_omitted_from_emission`: its list of keys that must be absent leaves
     out `machine_id`, `roster_seq` and `linux_*_size` (the substring `linux_x86_64` covers only some of them).
     `manifest-round-trip` states it for every None field.
4. **Timing and environment dependence (AGENTS.md: a wait is a hang detector, never a latency budget)**
   - `src/sys.rs::acquire_fails_fast_on_permanent_error` (Windows) asserts `elapsed < 1 s`. The contract is to
     return the original non-sharing error on the first try; the stopwatch should go.
   - `src/sys.rs::acquire_within_times_out_while_another_holder_has_it` asserts `waited >= 150 ms`. That is a timing
     lower bound the deadline logic already guarantees, so it adds nothing to the TimedOut contract.
   - `src/privatedir.rs::an_already_private_dir_is_not_rewritten_and_a_drifted_one_is_hardened` sleeps 20 ms so
     that a ctime change would show. On a filesystem with coarse ctime granularity, an unwanted chmod in the same
     tick would go unseen. The negative control depends on timing; `ensure-private-dir` states the chmod condition.
   - `src/roster.rs::an_unreadable_clock_fails_closed_rather_than_reading_as_1970` also asserts
     `now_unix() > 1_700_000_000`, which reads the real wall clock. That part samples no spec; drop it.
5. **Public behaviour with no test, so no spec was recovered for it.** These need specs written from the code:
   `pkg_check::Stamps::completed_older_index_pass`, `http::download_error_is_local_write`,
   `HandoffPolicy::names_producers` / `PolicyFile::names_producers`, `handoff_policy::adopt`'s log lines, and the
   `forgive_launch_of` and `named_launches` arms of the sentinel that the tests do not reach.
6. **Count.** The wave-2 chunk list says 159 tests; the files hold 161 `#[test]` fns. The difference is the
   platform-gated tests (`#[cfg(windows)]` in `sys.rs`, `#[cfg(target_os = "macos")]` and its negation in
   `codesign.rs`), which a host-filtered count drops. This file maps all 161.

## 6. Proof order (easiest high-value first)

Every spec is blocked by gap 0. Seal `150efe4a` closes it locally (plan, "Seal `150efe4a`"), so the first items
are the ones blocked by gap 0 plus the fewest real gaps, with a scalar core that E6 already admits.

1. **`derived-bounds-arithmetic`** (gaps 0, 3; 3 tests). `download_max_time_secs` is `u64` division and a
   `clamp`, the same shape as the clamp probe that publishes `certified` on seal `150efe4a`. `vendor_curl_cap` is
   one `max`. `verify_timeout_for` needs `Duration`, so prove its seconds core (`min(30 + len / 2097152, 600)`)
   first and lift it. It retires all three tests and gives every lane's monotone bound.
2. **The `elapsed`/`remaining` core of `full-pass-schedule-rule`** (gaps 0, 3 for the core; 5 tests once the
   `&self` part follows on gap 2). They are pure `i64` saturating scalars. The bounds
   `0 <= remaining(t, n, p) <= p` and "a clock set back holds a lane at most one period" are `omega`-class. This is
   the scheduler's safety property, and it is the one to bind to `AtpkgFullPassRule` later (gap 10).
3. **`elf-header-validation`** (gaps 0, 1, 3; 2 tests). It is a length guard followed by constant indices and
   `from_le_bytes`. It needs only a byte-slice carrier, and it is fail-closed security logic for the Linux binary
   admission path.
4. **`resume-plan-and-prefix-rules`** (gaps 0, 1, 3, 4; 4 tests). `resume_plan` and `keep_partial` are scalar `u64`
   (the struct return is the only carrier). The invariant "`!discard` implies `offset + remaining_cap = m`" is
   what keeps the total byte bound across resumes. `keep_partial_after_failure` and `range_refused` follow once
   `Code` (from `asset-failure-classification`) and `API` are citable.
5. **`policy-knob-predicates`** (gaps 0, 2, 3; 2 tests). These are const fns over `Copy` enums and an inclusive
   range test. They are the base lemmas of every handoff-policy spec (`for-build-and-hull`,
   `keeps-every-sealed-build`, `adoption-decision`).
6. **`api-host-predicate`, `transient-status`, `linux-target-names`** (gaps 0, 1; 1 test each). Each is a
   `&str` prefix test or a literal match. They are the smallest first users of the `&str` carrier (gap 1), and
   `API` is cited by four other specs.
7. **`curl-lane-option-sets`** (gaps 0, 1, 5; 8 tests, the largest collapse). Once `&str` slices are carriers, it
   is decidable by evaluating fixed arrays. It pins the no-credential, no-`--`, https-only and bounded-retry
   rules of every curl lane.
8. **`clock-fails-closed`** (gaps 0, 3, 13; 1 test) and then **`roster-admit`** (gaps 0, 1, 2, 12). Together they
   prove that an unreadable clock admits no roster.

The effectful specs (`advisory-file-lock`, `lane-slot-claim`, `ensure-private-dir`, `same-volume`,
`update-enabled-at`, `bundle-policy-read`, `boot-sentinel-state-machine`, `https-gate-before-spawn`,
`vendor-body-cap`, `codesign-run-mapping`, the hash arms) come last, on gap 8. Before then, factor out each
one's pure core (the sentinel record parser and its `Sigma` transitions, the `claim` decision, the
`read_bounded` verdict over a stat result) and prove that core early.

# aterm-uds: spec recovery from its 137 unit tests

> Mounted-volume acceptance is an explicit development task, outside ordinary tests:
> `targo --unverified bench -p aterm-uds --bench dmg_acceptance --profile test`.
> It may request macOS removable-volume consent. Every planned row must run; setup
> unavailability reports `COULD NOT RUN` (exit 3), an assertion failure reports `FAIL`
> (exit 1), and only completed controls pass. Release libraries omit these entrypoints.

This crate is almost all effect: descriptors, processes, sockets, kernel queries. Most specs are therefore
stated against an explicit platform model (gap 8), and each one names the pure decision layer that can be
factored out and proved first. Many of the functions carry `#[cfg_attr(trust_verify, trust::skip)]`
(fdpass, peer, process, rand, exitwatch, latest, holders, ownerlock, hangup, pspawn, spawn): a spec on one
of them first needs either a pure core factored out of the FFI shell, or the skip lifted. The difficulty
column says which.

## 0. Notation used in the statements

- `Tbl(P)`: the set of open descriptor numbers > 2 in process P. `Node(fd)`: fstat `(dev, ino)`. `OFD(fd)`: the open file description fd names. `CLOEXEC(fd)`: `FD_CLOEXEC` is set.
- `Unflagged(P)` = `{ fd ∈ Tbl(P) | ¬CLOEXEC(fd) }`, the descriptors an exec would carry.
- `K(P)`: the abstract kernel state of process P: `alive | zombie | reaped`, plus euid, ppid, cwd vnode, exe vnode and fd table. Each vnode is `live(path, rdev)` or `dead`. The "platform model", "kernel model", "fs model", "FIFO model", "flock model" and "SCM_RIGHTS model" in the statements are projections of `K` (audit §5, gap 8).
- `LibprocRead`: the abstract answer of one libproc call, `Ok(v)` or `Err(errno)`. `Failed::of` maps errno to `{Exited, Closed, Dead, Other}` (spec `errno-classification`).
- `dec(n)`: the shortest decimal spelling of n.
- `pidname(s) = Some(n)` iff `s = "aterm-" ++ D ++ ".sock"`, with D a non-empty run of ASCII digits and n = D parsed as u32 (overflow gives None).
- `WaitStatus(exit n) = n << 8`, `WaitStatus(signal s) = s`, as wait(2) encodes them.
- `shows(word, have) := (¬have ∧ word & (CREATE_NO_WINDOW | DETACHED_PROCESS) = 0) ∨ word & CREATE_NEW_CONSOLE ≠ 0`: the Windows console-window predicate `spawn::shows_a_console_window(word, have)` (§5.7).
- `SpawnPaths` = `{ spawn_with_two_fds, spawn, command().spawn/output/status/exec, an InheritStrip-forked child, a std Command with InheritNothing::inherit_nothing }`.
- Gap numbers are the rows of the table in `AUDIT-trust-for-test-migration-2026-10-15.md` §7 (historical internal audit). Gap 0 (an installed seal that publishes Clean-discharged rows) blocks every spec: seal `150efe4a` closes it locally, but admitting it to the machine's `trust` channel is owner-gated, so it is listed on every row.

## 6. Proof order (easiest high-value first)

Gap 0 comes first for all of them (a seal that publishes Clean rows; `150efe4a` does, locally). After that:

1. **Only gap 3 (E6 widening), pure scalar code:** `creation-flags-rule`, `cmsg-layout`. Seal `150efe4a` measured both as not admissible yet: `creation_flags` needs gap 1 for its `Console` parameter, and the cmsg helpers need gap 3 for their overflow asserts plus a `requires` on `n`. See the status note at the top. `creation_flags` is a `const fn` of `u32` bit operations and one guarded `match` on a fieldless enum: the easiest spec in the crate. It retires 3 tests, and its `¬shows` corollary is the only safety statement behind the Windows console tests. `cmsg-layout` is const evaluation per target and is the arithmetic `scan-control` and `fdpass-recv-ownership` stand on.
2. **Gaps 1 and 3: small enums and strings:** `errno-classification`, `disk-image-timed-out`, `path-under`, `win-sun-path-encode`. `Failed::of` is a five-arm `match` on `i32` returning a fieldless enum; it is the lemma both holder folds use.
3. **Gaps 1, 3, 5, 7: pure parsers and encoders over slices and `&str`:** `scan-control`, `token-name-for-sock`, `instance-sock-name`, `audit-token-accessors`, `procfs-start-parse`, `hex-encode`. `scan-control` is safe, pure, panic-free code with a clear loop variant and retires 5 tests; it is the security core of descriptor passing (no fd outside the control buffer, truncation always flagged). `token-name-for-sock` carries the injectivity corollary that keeps two sockets off one token file. `hex-encode` first needs its `trust::skip` lifted (§5.8).
4. **Pure decision layers with closures, generics or `&mut`:** `lifeline-read-until-cut`, `rand-fill-from`, `spawn-image-env`, `set-flags-noop-off-windows`, `off-the-targets`. Each needs gap 2, 11 or 13 for a higher-order or `&mut` argument; their decision layer needs no platform model (`rand-fill-from`'s device fallback and `off-the-targets`' fcntl half do). `off-the-targets` splits into a pure `placeable` range check (gap 3) and an fcntl half (gap 8).
5. **Pure folds behind an injected reader:** `holder-scan-fold`, `path-scan-fold`, `child-handle-reap-once`, deadline-gate (its `admit` core). Factor the libproc/waitpid calls behind a trait first; then each is a fold over abstract answers. `child-handle-reap-once` is a small state machine (an `Option` cache) over a waitpid oracle and retires 4 tests.
6. **Platform-model specs (gap 8):** `fdpass-argument-guards`, `peer-credentials`, `libproc-answers`, `lifeline-validate`, `lifeline-sweep`, `lifeline-carrier`, `spawnfd-exact-inheritance`, `command-stdio-placement`, `execvp-search`, `command-refines-std`, `command-builder-accessors`, the rest. Prove the factored pure halves (`validate_send`/`validate_recv`, `checked_pid`, the lifeline verdict classifier) as soon as gap 3 allows; the effectful halves wait on Trust's platform lane. `ctlstream-transport` (11 tests, but only the Windows half is aterm code), `spawnfd-exact-inheritance` (10) and `libproc-answers` (11 sampled, 10 primary) are the largest collapses and the most valuable once that lane exists.

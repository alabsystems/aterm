# aterm-sysprobe: spec recovery from its unit tests

Source: `crates/aterm-sysprobe`. The recovered spec table below maps 49 `#[test]` functions across
`src/tests.rs` (19), `src/jobs/tests.rs` (17), `src/procargs_tests.rs` (8) and `src/linux_tests.rs` (5),
recounted from §2's rows on 2026-11-04. Nothing was compiled or run for this file; the claims come
from reading the code.

Result: **29 specs**, covering **49 tests**. Every mapped test is a spec sample (§4).

## 0. Notation used in the statements

- `T` = `src/tests.rs`; other tests are named by their path from the crate root
  (`src/jobs/tests.rs::…`). Functions are named by their module under `src` (`linux::f` is in
  `linux.rs`, `jobs::f` in `jobs/mod.rs`, `jobs::darwin::f` in `jobs/darwin.rs`); a bare name is
  in `lib.rs`, except the job probe's `JobsReader`, `ProcFacts` and `tail_allowed` (`jobs/mod.rs`).
- `WL(t)` ("whole lines") = `linux::whole_lines(t)` = `t[..e].lines()`, where e = `t.len()` if t
  ends with `'\n'`, else (the index of the last `'\n'`) + 1, or 0 if t has none. So the torn last
  line of a text cut at `READ_CAP` is never parsed.
- `Key(t,k)` = `linux::keyed(t,k)`: the second whitespace token, parsed as `u64`, of the first line
  in WL(t) whose first token, less a trailing `':'`, equals k and whose second token parses; None
  when no line does.
- `sat+`, `sat-`, `sat*` are the `u64` saturating ops.
- `Effects(...)` marks a statement about the OS (procfs, sysctl, libproc, Mach), provable only with
  a platform model (gap 8). Its pure core, stated in a row of its own where one exists, is the part
  to prove first.
- `blocking_gaps` are rows of `docs/TRUST-LANE.md` (Blocking gaps). Gap 0 (the
  installed seal publishes no Lean-discharged row) is listed on every row. Gaps 6 (plain-Rust
  clause publication), 14 (the Clean elaborator) and 16 (soundness) apply to every row and are not
  listed.

## 5. Implied specs that look wrong, or disagree with the code

1. **Retired — `used_mib_of` saturated every addition.** It left with `machine_memory` on 2026-11-06;
   memory used is `MemoryDetail::used` (`memory-used`), which saturates every addition too.
2. **Retired — `macos::machine_memory` capped `used_mib` at physical memory.** `MemoryDetail::used`
   holds its sum to `total` and `mac_available` holds available to it, so
   `machine-memory-within-physical` holds by construction on every OS.
3. **Resolved — `linux::auxv_value` stops at `AT_NULL` (`0`).** `auxv_value` terminates at the first
   `k == 0` pair, so `auxv_value(bytes, 0)` is `None` and pairs past `AT_NULL` are unread.
4. **Resolved — scratch directory uses `aterm_tempfile::TempDir`.** `every_proc_read_is_bounded_to_4_kib`
   now holds an `aterm_tempfile::TempDir` so its scratch files are cleaned up on panic too.
5. **Resolved — child spawns use `aterm_uds::spawnfd::command`.** `a_groups_memory_is_its_own_members_footprint`
   and `a_groups_usage_is_its_own_members_cpu_and_runnable_time` build their children through
   `aterm_uds::spawnfd::command`. The +384 MiB-after-512 MiB margin remains a host-load heuristic, not a
   spec bound.
6. **Resolved — swap counter test checks monotonicity only.** `the_swap_counter_reads_on_this_host_and_never_runs_backwards`
   now asserts only `second >= first`, dropping the `< 1 GiB` host-load heuristic.

## 0. Notation used in the statements

- Test paths are repo-relative: `crates/aterm-cli/src/<file>::<test>`. Function names are relative
  to the crate root (`windowing::parse_window_request`, `manual::render`, `driver_unix::run`).
- `++` is string or list concatenation, `::` is list cons, `|x|` is length, and `'...'` is a string literal.
  Inside a literal, `\n` is LF.
- `decide(xs)` = `decide_args(xs.into_iter())`.
- `DIAG` = the names in `DIAG_COMMANDS` (8 of them: show-config, explain-config, doctor, list-fonts,
  show-face, list-themes, list-kitty-commands, exceptions).
- `VERBS` = `Verb::ALL` (22 variants). `NAMES` = `{v.name() | v in VERBS}`.
- `D` = `{-d, --directory, --working-directory, --startingDirectory}` (the directory flags of
  `parse_window_request`). `F` = `{-d, --working-directory}` (the flags the plain-launch gate knows), so `F ⊂ D`.
- `sep` is `:` on unix and `;` on windows. `split(p)` = `p.split(sep)`, and `join(xs)` joins `xs` with `sep`.
- `Doctor(sh, chk, origin, P, D, T, I, R, E, M)` = `doctor_checks_with_origin(..)` = `(report, code)`.
  `P` holds the privacy facts, `D` the debugger facts, `T` the devtools facts, `I` the instances result,
  `R` the recovery ledger, `E` the exceptions count and `M` the machine (copies) facts. `doctor_checks` is a
  `#[cfg(test)]` wrapper: it is `Doctor` with `origin = None`, `T = DevtoolsFacts::absent()` and
  `M = MachineFacts::absent()`. The doctor display specs below describe this test helper's
  legacy shell-health assessment. Since 2026-10-21, the composed `aterm doctor` in
  `crates/aterm/src/doctor.rs` uses `aterm_converge::Readiness` for its exit instead:
  unresolved checks and pending activation are non-green, including unmeasured notes.
  `doctor-exit-code` does not specify that composed command's exit.
- `Row(l, m, f)` = `pad_right(l,12) ++ pad_right(m.render(),5) ++ ' ' ++ first line of f ++ '\n'`. Each
  later line of `f` follows, prefixed by 18 spaces and ended by `'\n'`.
- `FS` is an abstract file-system model (lstat, stat, is_dir, is_file, mode, uid, mkdir, symlink, read).
  An FS spec assumes a POSIX PlatformSpec, so it is always blocked by gap 8.
- `Reach` is the injected `DevtoolsReach`. It is observed as the ordered trace of its calls:
  `ask_window(now)`, `list_terminal`, `open_pane`, `note_opened`, `await_on`, `say(words)`.
- `RosterText` = the `'static` strs of the manual (the `TOPICS` bodies, the `*_PAGE` consts and `HELP_HEAD`).
  A property over `RosterText` is decidable by evaluating constants.
- `Pages` = `render(None,None)`, `render(None,Some(sid))` and `render(Some(t),None)` for every `t` among the
  `TOPICS` names, `EXTRA_PAGES`, the alias keys of `render`, `NAMES` and `DIAG`.
- **Kinds**:
  - `contract`: a requires/ensures pair on one or more functions.
  - `table-property`: a property over a finite domain, decidable by evaluation.
  - `round-trip`: an encoder followed by its decoder.
  - `refinement`: the code agrees with a model or with another crate's rule.
  - `invariant`: a loop or composition invariant.
  - `other`: a liveness property, an effect-absence property or a platform axiom.
- **Gaps** are the rows of the table in `docs/AUDIT-trust-for-test-migration-2026-10-15.md` §7. Gap 0 (the
  installed seal publishes no Lean-discharged row) is listed on every spec because nothing is published
  until it is closed.

## 5. Implied specs that look wrong, or disagree with the code

1. **The doctor/exceptions grammar names the wrong token.** The tests are
   `lib.rs::doctor_operand_grammar_is_enforced_at_the_edge` and
   `lib.rs::exceptions_operand_grammar_is_enforced_at_the_edge`. The `[other, ..]` arm of `decide_args`
   binds `rest[0]`, so `aterm doctor --read-only x` reports unknown argument `"--read-only"`, and
   `aterm exceptions --all extra` reports `"--all"`. The tests check only the grammar text, so they miss
   this. Fix the arm to name the first token that does not fit, then prove the intended clause of
   `decide-diag-grammar`.
2. **`list-themes` has no `diag_report` arm.** The test is `lib.rs::diag_commands_advertised_and_dispatchable`.
   The `DIAG_COMMANDS` doc says `diag_report` handles every entry, but `list-themes` is routed by
   `theme_cmd::list_themes_alias`, and the test hides this with an `||`. The earlier pass stated
   "diag_report(c) is Some iff c in DIAG", which is false. `diag-registry-dispatch` corrects it.
3. **The earlier pass had two more errors.** Its font-and-theme-reports spec had a `list_themes_report`
   clause, but no such function exists in the crate. Its `verb-roster` said 15 variants, but `Verb::ALL`
   has 16. Both are corrected here (`font-reports`, `verb-roster`).
4. **A repeated directory flag gets two outcomes.** The test is
   `windowing.rs::the_plain_gate_only_knows_the_directory_flags_the_window_parses`. Its doc claims "one
   argv never gets two outcomes", but `plain_launch_is_policy_eligible` accepts a repeated `-d`
   (`-d /a -d /b`). `plain_launch_dir_operand` then returns the FIRST operand, while
   `parse_window_request` keeps the LAST. No test covers repeats. Either refuse a repeated F in the gate,
   or take the last operand.
5. **The doctor tests mostly run with two rows off.** Most doctor tests go through the `#[cfg(test)]`
   wrapper `doctor_checks`, which pins the devtools and machine facts to absent. So the production
   `doctor_checks_with_origin` is mostly sampled with those rows off. The specs are stated on the
   production function, and the wrapper should be deleted with its tests.
6. **The help text's SUBCOMMANDS lines are kept in step only by a test.** In
   `diag_commands_advertised_and_dispatchable`, the SUBCOMMANDS lines of `HELP_HEAD` are hand-written
   static text. Only this test makes "help_text advertises every DIAG entry" true. Render those lines from
   `DIAG_COMMANDS` so it holds by construction.
7. **Two constants are restated instead of imported, and their docs are stale.** The docs of
   `REROUTE_DIR_ENV` (lib.rs) and of `REROUTE_DIR_MARKER` and `EXEC_ROOTS_DIR` (manual.rs) say "this crate
   links atpkg for tests only". That is no longer true: atpkg is a normal dependency.
   `reroute_marker_and_shim_shape_match_atpkg` and `routed_shims_resolve_to_where_the_shell_execs` each
   police a restated constant that should be imported.
8. **A host precondition fails instead of skipping.** `the_session_child_sees_the_posture_of_its_mode`
   asserts a host precondition (inherited hard NOFILE > 8193). On a host with a lower hard limit it fails
   instead of skipping.
9. **What a Windows test checks depends on the host.** `driver_windows.rs::window_shell_default_is_the_spawns_default`
    asserts the pwsh facts only when pwsh is on PATH.
10. **A poll test checks its own loop.** `driver_unix.rs::closed_pipe_drains_buffered_bytes_then_consumes_hangup`
    exercises the test's own loop and the OS's poll semantics, not `drain_master`. Its 10 s poll timeout is a
    latency budget, but AGENTS.md says a wait is a one-minute hang detector.
11. **A test leaks a process-global stamp.** `version_text_names_the_running_copy_and_any_other` installs a
    process-global `BuildStamp` (a `OnceLock`) for the whole test binary, and it can leak into other tests.
    `version_text` should take the stamp as an input.
12. **A large probe output times out.** In `manual.rs::bounded_first_line_kills_a_wedged_probe`,
    `bounded_output` reads the child's stdout only after `try_wait` reports exit. A probe that writes more
    than the pipe buffer blocks until the limit and returns None. So the "answered as soon as it exits"
    clause holds only for small outputs, which is fine for `-vV` today.
13. **Some tests spawn children with a bare `Command::new`.** `driver_unix.rs::run_returns_the_shells_status_not_an_older_zombie_childs`,
    `the_shells_first_output_runs_the_hook_once`, `manual.rs::page_never_runs_a_pending_targo` and its
    siblings re-exec and probe children with a bare `std::process::Command::new`. AGENTS.md routes
    these through `aterm_uds::spawnfd::command`.
14. **Two pure functions have no test.** `push_utf16_unit` (surrogate pairing across batches, in windowing.rs
    and driver_windows.rs) and the repeat behaviour of `plain_launch_dir_operand` are untested.
    `push_utf16_unit` is a pure, high-value spec candidate worth adding: UTF-16 to UTF-8 with one U+FFFD per
    unpaired surrogate.

## 6. Proof order (easiest high-value first)

No spec is blocked by gap 0 alone (§1), so every proof waits on gap 0 plus one more small gap.

1. **`route-launch-table` and `poll-must-read`** (gaps 0 and 3). Both are finite tables, decidable by
   evaluation. `poll-must-read` is a `const fn` of i16 bit operations, so it is a `bv_decide` proof.
   `route-launch-table` is a 16-cell enum table, and it decides whether a launch forwards to a running
   window. Together they retire two tests and need only the E6 widening for bitwise ops and enum matches.
2. **`mark-table`, `exceptions-row`, `build-of`, `compare-toolchains` and `windowing-behavior-parse`**
   (gaps 0, 1 and 3). These are small pure matches over enums, `Option` and `&str`. `mark-table` and
   `exceptions-row` are leaf lemmas for `doctor-exit-code`, the property that no row except shell: moves
   doctor's exit code. `windowing-behavior-parse` guarantees that no typo selects Attach.
3. **`window-args`** (gaps 0 and 1). This is a one-line Vec construction. It is the first test of the
   non-scalar carriers.
4. **`agents-dir-mode`** (gaps 0, 3 and 12). This is u32 bit arithmetic, and the security-relevant mode
   rule for the agents directory. It is the first cross-crate citation, against `atpkg::store::Layout::ensure_dir`.
5. **`doctor-shell-row`, `rust-toolchain-row`, then `privacy-row`, `debugger-row` and `instances-row`**
   (gaps 0, 1, 3, and 12 or 7). Once these are proved, **`doctor-exit-code`** composes them (gaps 4 and 5)
   and samples 7 tests.
6. **`zone-offset-parse`, `prepend-path`, then `session-path-env`** (gaps 0, 1, 3 and 4/5/7). These are
   pure string functions with arithmetic or quantified ordering claims.
7. **The `decide_args` family** (`decide-run-options` retires 15 tests, plus `decide-diag-grammar`,
   `decide-leading-words` and `tool-candidate`) and **`verb-roster`**. This family is the
   highest-volume retirement in the crate, but it needs loops over a generic iterator (gaps 7 and 11).
   Fix §5 item 1 first.
8. **`parse-window-request-grammar`, `control-request-framing` and `plain-launch-gate`**. Fix §5 item 4 first.
9. **Manual specs**, which are decidable by evaluating constants once gap 7 lands (`manual-render-routing`
   samples 10 tests). Then the FS specs (gap 8), and last the `run-*` driver liveness specs and
   `devtools-hand-over-table` (gaps 8 and 13).

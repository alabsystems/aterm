## 0. Notation used in the statements

- Paths are relative to the repo root. In the TSVs, test names are `<file>::<fn>`, with `<file>`
  relative to `crates/aterm-phase/`. Functions are `<module>::<fn>`, with the module under `src/`.
- `rows: &[String]`, one `String` per screen row. `len` = `rows.len()`.
- `blank(r)` ⇔ `text::trim(r)` is empty, and `drawn(r)` = `¬blank(r)`. `trim`, `trim_start`,
  `trim_end` and `leading_spaces` are the crate's byte-level `text::` functions. `text-byte-trims`
  proves that they equal the `str` methods, so the other statements may read them either way.
- **Frame** `f = composer_frame(rows) = {top, bottom}`: the caret row `composer_index(rows)`, with a
  rule (`phase::is_rule`) directly above it and the first rule below it. "A frame exists" means
  `composer_frame(rows) ≠ None`.
- **Status block** `phase::status_block(rows, f.top) = {status, end, from}`. The status row is
  `status`, and the status line is that row rejoined over its Ink wrap (`status-block-walk`).
- **Live zone** of a screen read by its tail = `rows[reader::live_zone_start(rows,40)..]`. **Busy zone**
  = `rows[phase::busy_zone_start(rows)..]`. `blank_above(rows,k)` = rows with every row of index `< k`
  replaced by `""`.
- **Zone terminator**: the launch card's banner row (`turn::banner_row`), another composer's rule, or an
  `exit.resume` anchor row alone.
- **Parked block**: a row group that the vendor draws between the status row (or the last transcript
  row) and the top rule and that is no transcript. Examples: survey cards, drafts and ask cards, a
  rating aftermath, right-aligned banners and hints, a context indicator, blank rows.
- `anchor X` = `anchors::anchor("X")`, the vendor text pinned in `src/anchors.rs`.
- **`Render_CC(s, w)`** is a spec-level model of how Claude Code's Ink renderer draws abstract UI
  state `s` (a box, a dialog, a notice line) in a pane `w` cells wide. It is not in the code.
  **`InkWrap(line, room)`** is the wrap-ansi hard, non-trimming greedy word wrap that Ink applies;
  `wrap::rows_in` counts its rows. Specs that quantify over these models need gap 10 (model→code
  refinement) once the models exist.
- `Q` ranges over the quoting transforms in `quoted-box-refusal`.
- **table-property** is a finite table (fixture or const row → labelled reading). It is decided by
  evaluating the compiled function on each entry. Each corpus table is the only executable sample of
  a refinement `reader(Render_CC(s,w)) = s` until `Render_CC` is modelled. Keep the corpus as data
  (`include_str!`), not as `#[test]` fns.
- **No effects:** the crate has no `&mut self` and no I/O outside `cfg(test)`. Its specs are pure
  functions over row slices. Gap 2 (views) blocks none of them. Gap 8 (effects) blocks only the corpus
  loader that reads `src/fixtures` with `std::fs` (`launch-card-corpus`), until it embeds its data.
- **Gaps** are the numbers in the audit's §7
  (`AUDIT-trust-for-test-migration-2026-10-15.md` (historical internal audit)).
  Gap 0 (a seal that publishes Clean rows) is a prerequisite for every row, so it is left out of the
  column. Seal `150efe4a` closes it locally, but it is not installed on the machine's `trust` channel.
  Almost every spec needs gap 1 (`&str`/`String`/`Vec`/`Option`/enum/struct carriers) and gap 3 (E6
  body widening: calls, loops, matches). Most also need gap 5 (quantified clauses) and gap 7 (loops).

## 5. Implied specs that look wrong, or disagree with the code

1. **`cursor_inside_text` is true on the caret itself.** In
   `src/phase.rs::the_cursor_only_proves_text_it_stands_inside`, the function returns true for column 0
   and column 1: the cursor on the `❯` glyph and on the space after it. The doc and the test name say
   "inside the text", which starts at column 2. The intended spec is `col > 2`, but the test checks only
   2, 3 and 9. Fix the code (`col > 2`) before proving `cursor-inside-text`; as written, the spec
   states the code's `col ≠ 2`.
2. **The test pins a known false positive.** `src/wall.rs::a_monitor_events_payload_is_read_as_the_vendors`
   expects a monitor event's payload that opens with a wall phrase to read as a vendor wall, "so the
   day this is told apart shows up here". The spec this test implies is the defect. The real spec is
   that a payload is no vendor row, and today only transcript confirmation in `aterm-agent` enforces
   it. `wall-placement-owner-walk` is written with this exception named.
3. **A recall rule, not a correctness spec.** `src/wall.rs::the_owner_walk_on_its_measured_screens`
   requires two tool outputs to read as Auth walls "for the transcript to refuse": an MCP result of
   several blocks, and output under a PreToolUse hook. The screen reader accepts these false positives
   by design. Prove the placement rule, and state these two as admitted over-approximations rather
   than as part of the spec.
4. **An authoritative Idle mid-turn.** `src/codex_tests.rs::a_goals_next_turn_streaming_under_the_last_end_row_reads_ended`
   pins a running turn that reads Idle with `phase_authoritative == true`. That violates the reader's
   own contract that an idle reading is never authoritative mid-turn. The phase should probably be
   non-authoritative there. `codex-phase-end-row` records it as a blind spot. Decide before proving
   whether to fix the code first.
5. **A weakened assertion hides a wrong description.** `src/prompt.rs::a_title_whole_on_its_row_takes_no_row_under_it`
   asserts the description only with `ends_with`, because the description keeps the tail of the
   wrapped Tip row ("display only, a residual of round 20"). The implied spec (the description is the
   description row) is false in the code. `box-wrap-invariance` should state the strong form, and the
   code should be fixed to meet it.
6. **A quoted indicator can be read.** The doc of `context_left` admits that it reads a quoted indicator
   row of the last block when that row ends against this pane's right edge and no status row stands
   under the block. `src/phase.rs::a_quoted_indicator_in_the_last_block_is_not_read` covers only quotes
   off the edge. So "a quoted indicator is never read" is not the code's spec, and
   `context-left-grammar` does not claim it.
7. **`limit_notice` and `wall` can disagree.** `limit_notice` runs `footer_notice`/`banner_notice` with
   a classifier filtered to `reads_limited` kinds. A non-limit footer or banner notice (a context wall)
   can therefore be skipped and a lower-placed limit notice found. On a screen with both,
   `worker_phase` could read Limited while `wall()` names Context. Every test
   (`src/wall.rs::context_is_its_own_wall_and_the_quota_notices_are_none` among them) uses screens with
   one notice, so this disagreement is never checked. `limit-notice-wall-agree` keeps the single-notice
   hypothesis. The general spec ("the phase's limit is the wall's when the wall reads limited") needs
   a decision on which notice wins.
8. **Codex and Claude classified the same failure differently (resolved 2026-10-16).** In
   `src/codex_tests.rs::every_wall_row_is_read_by_kind`, Codex's `■ stream disconnected before completion: connection reset`
   becomes `ApiError{cause: Server}`. Under Claude's `ApiCause` taxonomy, a dropped or reset
   connection is Unreachable or CutOff. Supervisors that answer by cause therefore handle the same
   failure differently for the two programs. Unify the cause before proving `codex-wall-table`.
   Resolved on the 0.163.0 captures: a cut stream with no `last status:` is `ApiCause::CutOff`, one
   that names its status is `Server` with that code.
9. **A test pins the Unicode version.** `src/text.rs::the_byte_trims_are_the_char_trims` asserts that
   Unicode has exactly 25 White_Space chars. That pins the std/Unicode version, not the code. The spec
   (`text-byte-trims`) is equality with `char::is_whitespace`, whatever the count.
10. **The busy guard is never checked as a regex.** `src/reader.rs::each_reader_says_how_to_type_into_its_program`
    checks the busy guard by turning the regex back into text with
    `guard.replace("\\)", ")").replace('.', " ")`. A guard that over-matches (any char where a space
    was) would still pass. `guard-regex-contract` states the matching semantics, and
    `reading-composition` cites it.

## 6. Proof order (easiest high-value first)

No spec is blocked by gap 0 alone, because each one reads strings, rows or enums (gap 1). The order
below starts with the specs that need the fewest gaps beyond 0, and among those prefers the ones that
are lemmas for many others.

1. **`cursor-inside-text`** (gap 1). A scalar `match` on `Option<(usize,usize)>`. It is the first E6
   import that needs only an `Option`/tuple carrier, so it is the cheapest probe of gap 1. Fix §5.1
   first, so that the proved spec is the intended `col > 2` and not the bug.
2. **`reads-limited-table`** (gaps 1, 3). An enum `match` returning `bool`/`&'static str`. It is
   decidable by case split once enum carriers exist. `phase-priority`, `limit-notice-wall-agree`,
   `background-wall-priority` and `codex-wall-table` all cite it.
3. **`text-byte-find`, then `text-byte-trims`** (gaps 1, 3, 5, 7). The byte-level `&str` primitives.
   Every row reading in the crate goes through them, so they are the base lemmas for the other 80-odd
   specs. Each is one `while` loop over bytes with an obvious invariant. `text-byte-find` needs no
   Unicode model, so it comes first.
4. **`guard-regex-contract`** (gaps 1, 3, 5). A char map into a `String`, with no loop invariant
   beyond the map. It replaces the guard check that §5.10 shows is too weak.
5. **`anchor-table-invariant`** (gaps 1, 3, 7). A table property over `const` arrays, decided by
   evaluation. Every anchor-based grammar cites it.
6. **`reader-no-panic`** (gaps 1, 3, 7, 11). It is the highest-value proof per unit of effort. Trust's
   own panic-freedom obligations (slice bounds, overflow, unwrap) are exactly this spec, so it needs no
   functional statement. It also retires the panic sweep with a stronger, all-inputs result. The
   seal-150efe4a parser run showed that these obligations currently produce spurious refutations
   without loop invariants and path facts (gap 7). Expect to fix those Trust precision gaps here.
7. **`row-byte-readings`, `wrap-continues-line-end`, `prompt-box-holds`** (gaps 1, 3, 5, 7). These are

## 0. Notation used in the statements

- `Strip(s)` = `libtest::strip_ansi(s)`: removes every CSI sequence (ESC `[` … final byte in 0x40..=0x7E) and every other two-char ESC sequence. It is the identity on ESC-free text and idempotent.
- `Lines(s)` = `str::lines(s)`. `NonBlank(s)` = the lines of `s` whose trim is non-empty.
- `Hdr(l)` = `libtest::header(l)`: `Some(rest)` for a trimmed `Running rest` where `rest` contains `" ("`, ends with `)` and has no backtick; `Some(l.trim())` for a `Doc-tests …` line; else `None`.
- `Sh(w)` = POSIX sh word-splitting plus quote removal of `w` (no expansion: no `$` or backtick survives quoting).
- `JSONv(t)` = the RFC 8259 value text `t` denotes. `TOMLs(t)` = the string a TOML basic-string literal `t` denotes.
- Scopes: `W` = `Scope::Workspace`, `P(ps)` = `Scope::Packages(ps)`, `C(base, cs, lib)` = `Scope::Changed`. `crates(s)` is `[]` for `W`, `ps` for `P(ps)`, `cs` for `C`. `Empty(s)` ⇔ `s = C(_, [], _)`.
- For a plan `p: Vec<StageSpec>`: `Aw(p, i)` = `sched::awaited(p, i)`, `Ready(p, st, dn, run, i)` = `sched::ready`. A scheduler execution is any interleaving produced by "start `i` only when `Ready` holds; finish any running stage".
- `Run{ok, output, code, spawn_error}`. `EnvFail(r)` = `Run::environment_failure(r)`.
- Outcome tags: `Ok`, `Skip`, `GF` = `Fail(GateFailed)`, `CNR` = `Fail(CouldNotRun)`.
- POSIX process model: a child started by `exec::run` leads its own process group. "Group" means that group's members; "leader reaped" means `waitpid` has collected the leader. Signals act as POSIX specifies.
- `DEV`, `RELEASE`, `CHECKS`, `WORKSPACE_BUILDS`, `TY_ONLY_CONFORMANCES`, `WEDGED`, `OBJC_DRIVES` are the crate's constant tables of those names.

**Blocking gaps** are the row numbers of the gap table in `docs/AUDIT-trust-for-test-migration-2026-10-15.md` §7.
Gap 0 (the installed seal publishes no Lean-discharged row) is a prerequisite for every spec, so every row lists it;
no spec here is blocked by gap 0 alone. Gaps 14 (Clean elaborator coverage), 15 (test→spec tooling), 16 (soundness)
and 17 (runtime harness) apply to the whole migration and are not repeated per row. In short: string and table
logic over `Vec`/`String` with loops needs 1, 3, 5, 7 (and 6 to publish SMT-proved `ensures`); process, signal and fs
specs need 8; thread, pool and closure specs need 13 (and 11 when generic); a spec citing a callee's postcondition
needs 4; methods on `Report` and `Ctx` (`&mut self`, self-by-value builders) need 2; scheduler and kill-protocol
specs that want a `ty_model!` with a conformance binding need 10.

## 5. Implied specs that look wrong, or disagree with the code

1. **`testrun-record-codec`: the test's doc overclaims.** `testrun.rs::a_record_round_trips_and_a_torn_one_is_refused` says "anything that is not a whole record is refused rather than read short". That is false: `Record::decode` accepts any prefix of `encode(r)` that ends exactly at a token-group boundary, so dropping the last whole `env\0K\0V\0` triple decodes to a SHORTER valid record. The test only samples cuts 1 and 3 bytes from the end, both mid-token. The true spec is canonicity (`decode(b) = Some(r) ⇒ encode(r) = b`), as stated in §1. **Action:** to make torn files refusable, add an end marker or a length to the format, then strengthen the spec to `decode(b) = Some(r) ⇒ b = encode(r)` for whole files only.
2. **`cli-parse-values`: `-p=X` is not accepted.** The implied spec "every spelling of `-p` is accepted" fails for `-p=X`. Inline values are split only for flags that start with `--`, so `-p=aterm-grid` falls into the `-pX` arm and selects a package literally named `=aterm-grid`. cargo and clap accept `-p=X`. No test covers it. **Action:** strip a leading `=` in the `-pX` arm (the safe, cargo-compatible fix), then state (a) with `-p=X` included.
3. **`stages-gated-features`: one assertion tests the tree, not the function.** The last assertion of `stages.rs::the_gated_features_are_read_from_the_manifests`, `gated_lint_features(<the real repo>) ≠ []`, checks a fact about the current checkout (via `CARGO_MANIFEST_DIR/../..`). It goes red if the repo stops having gated targets. **Action:** drop that assertion when the test is retired; it is not part of the spec.
4. **`exec-load-readers`: timing test.** `exec.rs::the_in_process_load_is_a_load_and_agrees_with_the_older_reading` retries and judges by wall-clock sampling (§4). **Action:** delete.
5. **Metadata.** The wave-2 chunk file counts 281 tests for aterm-verify; there are 280 `#[test]` attributes. The 281st is the doc-comment hit in `src/stages.rs` (~line 497).

### 5. Implied specs that look wrong, or disagree with the code

1. **Stale refusal.** The doc comments at gate.rs:2387 and :3259, and the message of
   `an_override_inside_the_workspace_is_still_refused`, say `cell_target_dir` refuses a cache inside the
   workspace. `cell_target_dir` has no such check. Either the docs are stale or a refusal went missing.
2. **Doc says widest, code is narrowest.** The doc on `median_sign_interval` says it returns "the widest
   symmetric pair whose exact binomial coverage is still at least 95%". The code scans the rank downward
   from (n−1)/2 and returns the first rank that reaches 95%, which gives the NARROWEST such interval. The
   test `the_median_interval_has_textbook_coverage` pins that narrowest answer, (1, 8) for n = 10. The code
   is the standard construction, so the doc is what is wrong. `stats-median-sign-interval` states the code.
3. **Green tests that never ran.** `a_planted_include_only_source_reds_the_fmt_sweep_and_greens_when_fixed`,
   `a_rustfmt_toml_that_contradicts_its_manifest_is_a_finding_until_it_is_written` and
   `a_tree_with_no_rustfmt_toml_at_all_is_a_finding_not_a_pass` each print SKIP and return (a pass) when
   trustfmt or git is missing. A green run then claims a check that never ran, against AGENTS.md's
   "report what actually ran".
4. **Unguarded arithmetic.** In `cells_verdict` (reached by 8 tests), `let unread = own_total - own_checked;`
   is a usize subtraction with no guard, so a report with own_checked > own_total panics. No test covers
   it. `cells_cost_line`'s `.sum()` of u64 secs and `fill_line`'s `n + c` have the same kind of
   overflow precondition. All three are recorded as `requires` in their specs. Each should either be
   proved unreachable from the callers or replaced by a saturating or checked form.
5. **Tests that pin the live tree.** `the_fmt_sweep_reads_each_crate_s_own_edition`,
   `the_proc_macro_carve_out_comes_from_the_manifest` and `the_patch_table_is_read_from_the_root_manifest`
   pin facts about the current tree (aterm-wasm is edition 2021, which crates are proc macros, which crates
   are patched). They go red when a manifest changes, even though the code is right. The general
   resolution functions are the specs, and the tree facts are data.
6. **A hash collision claim.** `each_checkout_gets_its_own_default_cells_cache` asserts `assert_ne!(a, b)`
   for two paths. That claims their FNV-1a digests do not collide, which is true for these two samples
   only. The real guarantee is the key's format plus FNV's distribution, not injectivity.
   `gate-checkout-cache-key` states only the format.
7. **Box-dependent outcomes.** `a_shim_for_the_hosts_own_triple_is_declined_by_that_cell_and_by_no_other`
   and `the_shipped_policy_reads_and_narrows_from_every_cells_own_machine` call `rustc_host_triple()`, which
   needs the live pinned toolchain (`expect`). The policy test's "needs at least one cshim row to audit"
   assertion also depends on the host triple. The specs quantify over the host instead.
8. **A substring check that adds nothing.** In `a_schema_is_the_integer_one_never_a_bool_or_a_float`, the 1.0
   case asserts the error contains "startup_phase_schema=1", which is also a prefix of the real
   "startup_phase_schema=1.0" message. Only `expect_err` carries the property.
9. **A wall-clock test.** `utc_date_is_iso_shaped` reads the clock and asserts the date starts with "20". It
   fails on a box whose clock is unset (1970) or after 2099. Its shape part is subsumed by
   `trend-civil-date-rfc3339`.
10. **Undocumented strictness.** `parse_cell_policy` detects comments on the trim_end'd line, so an indented
    `  # note` is an error, not a comment. That fits "strict", but the doc does not say it.
11. **Chunk metadata.** The chunk list reported 142 tests for xtask, but the files hold 145 `#[test]` fns.

### 6. Proof order (easiest high-value first)

No spec here is blocked by gap 0 alone. The cheapest rows need gap 0 plus one more gap: 3 (a float or
integer body widening) or 1 (struct carriers). They come first.

1. **`floors-compare`** (gaps 0, 3). Straight-line f64 with one multiply and an inclusive boundary. It
   retires 2 tests and is the per-key lemma `floors-judge-against-baseline` (5 tests) is built on. It is
   the smallest case that forces a float model into E6, which 30 specs here wait on.
2. **`cat-abba-order`** (gaps 0, 3). Integer parity only. It retires 1 test and is the parity lemma that
   `compare-schedule-protocol` and the ABBA cancellation theorem cite.
3. **`gate-cell-report-skipped`** (gaps 0, 1). A struct literal and a const enum match. It is the first
   use of struct and String carriers, and it is the row shape `gate-cells-verdict` (8 tests) reasons about.
4. **`trend-civil-date-rfc3339`** (gaps 0, 1, 3). Pure integer arithmetic (Hinnant's algorithm) with a
   round-trip characterisation. It retires the wall-clock test (§5.9) along with the exact one.
5. The remaining **gaps 0, 1, 3** rows, each a straight-line pure function: `gate-cell-cache-root-choice`,
   `gate-lint-verdict-line`, `gate-package-id-name`, `trend-chip-of` and `arena-socket-path-bound`.
6. Once gaps 5 and 7 land, the two big collapses: **`gate-cells-verdict`** (8 tests, discharging §5.4's
   precondition) and **`trend-judge`** with `trend-resolve-ledger-box` (9 tests between them).
7. Effect specs last. For each one, prove the factored pure decision as soon as its carriers allow.
   For example, `classify(present, ok, stdout)` for `gate-fmt-workspace-pass-classification` needs only
   gaps 0, 1 and 7. The shell waits on gap 8, and the thread-based ones on gap 13.

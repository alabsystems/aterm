# aterm-verify: the specs its tests stand for

Each row of §1 states what a group of the crate's tests samples, for proof against the compiled
Rust; §2 maps each test to the spec that retires it, and a test no map row names has no
spec yet. None is proved. A second part, at the end, covers the perf lanes, the cells reader and the
wasm glue. The statements come from reading the code: re-read a row's functions before proving it.

Paths in this file are relative to `crates/aterm-verify/` unless they start with `crates/`.

The perf lanes, the cells reader and the wasm glue have their own part at the end.

## 0. Notation used in the statements

- `Strip(s)` = `libtest::strip_ansi(s)`: removes every CSI sequence (ESC `[` … final byte in 0x40..=0x7E) and every other two-char ESC sequence. It is the identity on ESC-free text and idempotent.
- `Hdr(l)` = `libtest::header(l)`: `Some(rest)` for a trimmed `Running rest` where `rest` contains `" ("`, ends with `)` and has no backtick; `Some(l.trim())` for a `Doc-tests …` line; else `None`.
- `Sh(w)` = POSIX sh word-splitting plus quote removal of `w` (no expansion: no `$` or backtick survives quoting). `TOMLs(t)` = the string a TOML basic-string literal `t` denotes.
- Scopes: `W` = `Scope::Workspace`, `P(ps)` = `Scope::Packages(ps)`, `C(base, cs, lib)` = `Scope::Changed`. `crates(s)` is `[]` for `W`, `ps` for `P(ps)`, `cs` for `C`. `Empty(s)` ⇔ `s = C(_, [], _)`.
- For a plan `p: Vec<StageSpec>`: `Aw(p, i)` = `sched::awaited(p, i)`; a stage is Ready when `sched::ready` holds for it. A scheduler execution is any interleaving of "start `i` only when it is Ready; finish any running stage".
- `Run` has fields `ok`, `output`, `code` and `spawn_error`. `EnvFail(r)` = `Run::environment_failure(r)`.
- Outcome tags: `Ok`, `Skip`, `GF` = `Fail(GateFailed)`, `CNR` = `Fail(CouldNotRun)`.
- A child started by `exec::run` leads its own process group; "group" means that group's members, and "reaped" means `waitpid` has collected it. Signals act as POSIX specifies.
- `DEV`, `RELEASE`, `RELEASE_TREE`, `RELEASE_BUNDLE`, `CHECKS`, `OBJC_DRIVES` are the crate's constant tables of those names. `R(a)` is the release set of argv `a`: `RELEASE_TREE` under `--tree`, `RELEASE_BUNDLE` under `--bundle`, both concatenated with both, else `RELEASE`; then, when `a` has any `--checks` value, only the checks those values list (each value split at commas); all of `RELEASE` when a listed name is no check of those, which only a help parse returns Ok with.
- **Blocking gaps** are rows of the gap table in §7 of `docs/AUDIT-trust-for-test-migration-2026-10-15.md`. Gap 0 (the installed seal publishes no Lean-discharged row) blocks every spec and is listed in every row. Gaps 14–17 (Clean elaborator coverage, test→spec tooling, soundness, the runtime harness) apply to the whole migration and are not listed.
- A `tests/gate_contract.rs` test is mapped to the spec whose end-to-end clause it samples; it retires only once that clause (usually gap 8) is proved, not with the pure core.

### 0. Notation used in the statements

- Paths are relative to `crates/aterm-verify`. Test ids are `<file>::<test fn>`.
- `lines(s)` = `s.lines()`; `ws(s)` = the `s.split_whitespace()` tokens; `join(sep, xs)` is String join;
  `sorted`/`dedup` are over `Ord`. "starts with" and "contains" are the `&str` methods, or the `Path`
  methods (which compare whole components) when the operands are paths.
- A std or `spawnfd` `Command` is observed as `(program, args: [OsString], envs: [(key,
  Option<value>)])`, its `get_program`/`get_args`/`get_envs` projections.
- An `aterm_json::Value` is a finite tree. `number(j, k)` = `j.get(k).as_f64()` filtered to finite
  values. `round3(x)` = the f64 parsed back from `format!("{x:.3}")`.
- `≈` means `|x − y| ≤ ROUNDING_MS` (0.06 ms), as in start.rs.
- In stats.rs, `s` = the copy of `v` sorted by `f64::total_cmp`, and `n = |v|`.
- **Effect specs** (fs, process, signal, socket, clock) state the observable postcondition. Each one
  first needs its pure decision factored out (`docs/PLAN-tests-to-specs-2026-10-15.md`, "Order of
  work", step 4). The pure half is provable once gaps 1/3/5/7 land; the effectful shell waits on gap 8.
- **Floats.** Many specs use f64 arithmetic. The audit §7 table has no float-model row, so specs that
  need IEEE-754 reasoning (NaN, ordering, rounding) are listed under gap 3 (E6 refuses floats), the
  nearest row.
- **Gap 0** (the installed seal publishes no Lean-discharged row) blocks every spec. It is listed in
  every row so that the histogram is honest. No spec here is blocked by gap 0 alone.

3. **Resolved — `utc_date_is_iso_shaped` checks `YYYY-MM-DD` without a wall-clock century pin.** It now
   asserts ASCII digits and hyphens across all 10 positions and checks `civil_date` directly across
   centuries (`1970-01-01` and `2100-01-01`).

## 0. Notation used in the statements

- Functions are `module::fn` inside `crates/aterm-link/src`. `Type::{a,b}` lists several
  methods. A name outside the crate (`aterm_types::…`, `aterm_codec::…`, `astream_cap::…`,
  `aterm_uds::…`, `aterm_ctl::…`, aterm-gui control verbs) is a cross-crate callee (gap 12).
- `is_principal`, `is_topic`, `is_kind`, `is_verdict`, `via_ok`, `is_fleet` are
  `aterm_types::fabric_grammar`'s closed word grammars. `KINDS`, `VERDICTS` = {handled,
  refused, deferred}, and `WAITING` = {ask, task} are its closed sets.
- `pct` = `crate::pct`, the percent codec. The lemma used throughout:
  `pct::decode(pct::encode(s)) = s`, and encode's output is printable ASCII.
- `segs(s)` = `s.split('/')` as a list. A well-formed subject has an empty first element and
  is matched left-anchored, by position.
- `kv(line, k)` = the value of the first ` k=` token of a space-separated line.
- `B` is a `bridge::Bridge` state. `r` is an owed receipt `{sid, rid, off, from, kind,
  verdict, earlier_log}`. A session's inbox lane is `/f/<fleet>/in/<node>/<sid>/<src>/<kind>`.
  The sender's ack lane is `receipt_lane(B, r.from) ++ "/ack"`.
- `ev(sid)` = the records the bridge publishes on a session's ev face (`ack …`,
  `unacked re=<off> verdict=<v> reason=<no-lane|lane-cap|log-replaced|refused>`, `gap …`,
  `log-replaced head=… log=… was_log=…`, `halt-kept by=…`).
- `LogWitness{high, id}` is what the node last knew of the bus log. `in_force(B)` = the on
  halts of `B.halts` ∪ `B.kept_halts`. "The bridge holds (s, t)" means its topic state lists
  topic t for session s.
- "∀ execution" ranges over every interleaving of bridge kills and restarts, broker
  restarts and outages, lost acks and endpoint lane loss. Specs stated this way (kind
  `invariant` or `refinement` over the Bridge) are fixture-driven today (FakeVerbLane,
  FakePushLane, in-process astream brokers, the world suites in `crates/aterm/tests/fabric_world`,
  which run the real `aterm` binary and `aterm link serve`). Each is proved as a `ty_model!` of
  the protocol plus a refinement of the Bridge's step functions. Their effectful shells wait on
  gap 8. Their pure cores (classification, routing, commit floor, cursor rules, receipt gate)
  are factored out first.
- Gap 0 (a seal that publishes Clean rows) blocks every spec, so it is not repeated in the
  `blocking_gaps` column. That column lists the gaps beyond 0. Seal `150efe4a`, built
  locally (PLAN §"Seal 150efe4a"), closes gap 0 for local work. Admitting it to the
  machine's `trust` channel is owner-gated.

   and wraps in release, possibly to a tiny window or to a zero window the zero check never
   sees. The implied spec `notify-rate-flag` (total, never panics) is false today. Fix it
   with `checked_mul` and a refusal before proving it
   (`src/notify.rs::the_rate_flag_refuses_a_budget_that_would_drop_everything`).
2. **Prose-pinning stands in for a spec.** `enable::fix_for` dispatches on warning prose
   (substring matching), and `every_warning_shape_has_a_fix` /
   `a_fix_picks_the_remedy_the_warning_names` pin a hand-copied list of warning sentences.
   Nothing ties that list to the range of `fabric::warnings`, so a new warning with no fix
   still passes. `fix-for-every-warning` can only be stated over a closed warning grammar
   (an enum rendered to text). Make the enum first.
3. **The per-session maps are one type.** Every sid-keyed map and set is a field of one
   `PerSession` value whose `prune_to` destructures every field, so a new map cannot be added
   without the prune naming it. `src/bridge.rs::every_per_sid_map_is_pruned_to_the_roster`
   fills every field and drives the prune; `per-sid-maps-pruned` is that type invariant.
4. **Environment-dependent assertions.**
   - `enable.rs::review_two_roots_never_share_a_label` ends by asserting that this
     machine's `login_home()` is absolute.
   - `bridge.rs::the_node_row_carries_a_real_host_name` passes vacuously with no uname or
     `/etc/hostname`, and otherwise asserts on the host's name.

   None of these belongs in the spec.
5. **Clock-bound assertions.**
   - `link_state.rs::review_a_bridge_that_cannot_finish_its_attach_never_reads_connected` and
     `a_broker_path_nothing_listens_on_is_stalled_and_never_connected` sample a safety
     property over 8 s / 3 s windows, so a slow machine samples fewer states.
   - `receipts.rs::post_wait_ack_returns_the_recipients_verdict` polls in its acker thread
     with a 50 ms sleep and its own 60 s deadline instead of the harness `until`.
6. **A loop that looked like a retry (resolved 2026-10-16).**
   `topic_gap.rs::an_add_evicted_from_the_timeline_is_learned_after_the_gap` re-ran up to 5
   rounds, doubling the fill, when the kernel socket buffer absorbed the add, and under
   parallel load it also raced the fresh session's adoption and the bridge's owed post-seed
   read against the stop. It now runs once: the endpoint's debug-only `timeline` push hold
   puts the add in the hole by construction, and a GAP the bridge publishes before the add
   proves it owes no other read. The liveness clause of
   `topic-sampling-refines-announcement-model` still replaces it.
7. **A weaker test than its spec.** `receipts.rs::inbox_get_at_an_offset_fetches_a_record_the_ring_dropped`
    accepts `ERR timeout` for an offset past the head. `answer_fetch` answers
    `err=no-record` for a record the log never held, and `fetch-at-offset` states that.
8. **Stale docs.** In `crates/aterm/tests/fabric_world/receipts.rs`:
    - The module doc says a bridge without `--receipts` sends none. Receipts are on by
      default, and `receipts_off_sends_no_ack` needs `--no-receipts`.
    - The doc claims a `--peek` earns no receipt, but no test checks that.
    - `inbox_get_at_an_offset_…` describes a filler human `<src>`, but the code publishes
      under 16 agent srcs (`a-fill0..15`, trust=agent).
    - `post_wait_ack_returns_the_recipients_verdict` passes `--receipts` though it is the
      default.
9. **Implicit three-way kind.** The helper `assert_uncertain_in_flight_waits`
    (`bridge.rs::a_damaged_in_flight_entry_stops_recovery_until_it_is_repaired`) handles the
    kinds `listing` and `entry` explicitly and reaches `damaged` only through its else
    branches. It works, but `publication-exactly-once` should name all three.
10. **Chunk metadata was wrong.** The recovery chunks were labelled 348 + 8 = 356 tests,
    but their files hold 403 + 10 = 413 `#[test]` fns (re-counted for this file). This
    document covers all 413.

## 6. The specs I would prove first (easiest, high value)

None of the 135 specs is blocked by gap 0 alone. Every one needs at least a non-scalar carrier
(gap 1), a `&self` view (gap 2) or E6 widening (gap 3). The cheapest ones need only gaps 1 and 3, or
2 and 3, with no effects, loops or cross-crate calls (`forged-self-window` adds gap 11 for `BTreeSet<u64>`):

1. **`incarnation-adoption`** (`adoptable`, `presence_inc`, `next_incarnation`).
   `next_incarnation` is `u64` arithmetic with `checked_add`, `max` and a bound, an
   `omega`-class proof once E6 admits `checked_add`/`max` (gap 3). `adoptable` is an
   `Option<u64>` match (gap 1, `Option` carrier). It retires 2 tests, and it is the arithmetic
   that keeps an attach inside the will space, which `node-identity-and-lifecycle` relies on.
2. **`log-replaced-judge`** (`LogWitness::replaced_by`, `Bridge::judge_log`).
   `replaced_by` is a `u64` compare plus an `Option<LogIdentity>` equality (gaps 1 and 3).
   `judge_log` adds one `&self` read (gap 2). It is the primary spec of 2 tests (one unit, one world) and is the
   decision every log-switch clause of `log-identity-isolation`, `halt-kept-across-logs` and
   `receipt-gate` (23 tests between them) is conditioned on.
3. **`trust-of-address`** together with **`expired-span-text`** and **`forged-self-window`**.
   - `trust_of` is a `starts_with` on `&str` returning a `&'static str`.
   - `span_of` is `u64` div/mod into `format!`.
   - `forged_self` is a `BTreeSet` membership plus `first()`.

   Each is a first test of the `&str`/`String`/`BTreeSet` carriers (gap 1) on a body small
   enough for E6. `trust_of` is the security label every delivered record carries
   (`attribution-routing-trust`, `traffic-classification`).

Runner-up: **`notify-rate-flag`** right after the §5.1 fix. It is a small parser with one
checked multiplication. It is the only spec here that is false today, so proving it is the
real deliverable of that bug fix.

After those come the pure string codecs with the most tests behind them: `render-safe-one-line`
(3), `body-encode-decode-roundtrip` (4), `glance-fields-bounded` (4), `state-record-codecs` (6) and
`ctl-reply-framing` (4). Each needs gaps 1, 3, 5 and 7 (carriers, widening, quantifiers, loops) and
mostly gap 12 for the shared grammar. Closing gap 1 plus gap 7 unblocks most of this tier at once.

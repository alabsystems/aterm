## 0. Notation used in the statements

- Paths are relative to `crates/aterm-update`. Function names are `module::fn`, with the module
  path relative to `src/`. When a list entry starts with a bare `Type::`, the type lives in the module
  named by the entry before it. In the map, a test is `file` plus its fn name, with any inline
  module prefix kept (`survey::…`).
- Saturating arithmetic: `a ⊕ b`, `a ⊖ b`, `a ⊗ b` are saturating add, sub and mul. `lc(x)` =
  `to_ascii_lowercase`, `ci(a,b)` = `eq_ignore_ascii_case`. `chars(s)` counts code points.
  `dropWhile`, `map` and `filter` are the usual list functions.
- `passing(r)` := `r ∋ PASSING_REFUSAL_KEY` (`lib::is_passing_refusal`). `verdict(r)` := `¬passing(r)`.
  `needs_person(r)` := `¬passing(r) ∧ (install::is_rollback_source_refusal(r) ∨ r ∋
  INSTALL_LOCATION_REFUSAL_KEY ∨ r ∋ "does not run from an installed bundle")`.
- `canonical(c)` for a health class: `apply → apply`, `pipeline | stage → pipeline`, anything else →
  `manifest` (`lib::health_class_canonical`).
- `fmt(t)` = `aterm_types::rfc3339::format_rfc3339(t)`, `parse` = `rfc3339::parse_utc`. Cross-crate
  lemma used throughout (gap 12): `fmt` is injective and order-preserving under byte-lexicographic
  comparison on its range.
- `triple(v)` := `parse_release_tag("v"-prefixed v) = Candidate([a,b,c])`
  (`aterm_update_core::tag`, gap 12).
- Staging `s` (written `St` in the Linux-free manifest and status specs): the scratch roots with
  `s.status` (status.toml), `check_receipt::path(s)` (check.toml), `s.ready` (ready.toml),
  `s.staged_app`, `s.floor()`, `s.health()`, `s.failed()`, `s.trial()`, `s.installed_receipt()`,
  `s.apply_lock`, `s.stage_lock` and `s.download`. `read_publishable(St)` = `Ready::read(St.ready)`
  filtered by `is_publishable`. A spec over an effectful function is a Hoare triple over the abstract
  disk state these files denote. **Recommendation, for every such spec:** factor a pure judge over the
  parsed contents and prove that first. Where the judge is missing, the statement names it
  (`judge_receipt`, `lock_cycle_step`, `zip_claim_of_bytes`). Each factoring takes gap 8 off that
  spec's pure half.
- `H` is the Health record. `step_*` is the pure transition of each `Health::record_*` with `now`
  injected. The disk wrappers are read ∘ step ∘ write under `health.toml.lock`. The write is a no-op
  only where the statement says so.
- A **refinement** spec means: each real call, projected onto the named `aterm_spec` `ty_model!`
  machine, is a successor under the named action and preserves every invariant. Its `Buggy=k`
  negative control is the matching mutant. The models are in `aterm_spec::derive` (gap 10).
- Cadence constants: `LONGEST_WAIT` = 18 min 3 s and `STALE_CHECK_AFTER` = max(5·LONGEST_WAIT, 4 h)
  (`cadence_bounds`).
- Linux lane: `Ctx` = `linux::Context`, `S` = the State record at `Ctx.dir/state.toml`, `T` =
  `S.trial` (old `O`, new `N`, starts, last-start clock, healthy, window_proven), `bytes(p)` = sha256
  of the file at `p`, `Lanes(T)` = {healthy, window_proven}. "A v0.98 save" means reading `S` into
  the v0.98 shape and writing it back, which drops the stamps, window_proven and displaced.
- Constants: `BUDGET` = `LINUX_TRIAL_LAUNCHES` = 3; `W` = `START_SETTLES_SECS` = 20; `SPARES` =
  `LOST_STAMP_SPARES` = 8; `PA` = `PERSISTENT_AFTER` = 3; `BUSY` = `BUSY_ANNOUNCED_AFTER` = 120;
  `STDERR_KEEP` = 512; `RETRY` = `RETRY_BACKOFF_SECS` = [900, 3600, 14400, 86400]; `MOMENT` =
  `MOMENT_BACKOFF_SECS` = [0, 900, 3600, 14400]; `FRESH` = `ROSTER_FRESHNESS_SECS` = 86400;
  `REREAD` = `ROSTER_RECONFIRM_AFTER_SECS` = 3600; `SKEW` = 60.
- **Shell subjects.** The `sh-*` specs have `tools/install.sh::*` functions. They are statements about
  the bash 3.2 installer, not about Rust. No Trust lane can prove them today, and no row of the
  audit's gap table covers a shell subject. Their column cites gap 8 as the nearest row. They need a
  new gap: either a shell semantics, or a Rust-reference refinement harness for the differential ones
  (`sh-*-equiv`). Until that gap exists, their 61 tests stay as they are.

## 5. Implied specs that look wrong, or disagree with the code

1. **Likely code bugs, or unintended boundaries**
   - `dev_channel::classify`: when major and minor are equal and only the running patch is older
     (0.93.0 vs v0.93.1), the result is `Behind{releases: Some(0)}`. `words()` renders that as
     "0 releases behind aterm v0.93.1". No test covers this case. The module says the count is a minor
     count, so the zero-count case looks unintended. `dev-lag-classify` states the code as it is; decide
     the intended words before proving it.
   - `cadence::Cadence::hold_remaining`: a hold whose epoch equals `now` exactly gives
     `checked_duration_since = Some(0)`, which is floored to `HOLD_FLOOR` (60 s). The doc says a passed
     hold is simply over, so the boundary is one tick off the doc. No test covers equality.
     `cadence-nominal-closed-form` states the code (`u ≥ now`).
2. **Stale or mislabelled tests**
   - `status::latest_tag_is_schema_one_optional_sticky_and_readable_by_an_older_reader`: its comment
     says the second `record()` is "a later writer that set nothing — `record` cleared the delivery
     facts". `record()` never clears `DELIVERY`; the tag is carried from the in-memory
     `DELIVERY.latest`, not from the file. Only the `in_memory = false` iteration of
     `cache_rechecks_its_stage_and_never_rebinds_authority_on_a_status_write` exercises the file-carry
     path it claims to cover.
   - `manifest::a_quarantine_suppresses_forever_while_the_shape_it_used_to_take_does_not`: its last
     block says a timed stage failure "REPLACES the quarantine … last write wins". `record_timed`
     first moves a prior quarantine into quarantine.toml, so the artifact stays quarantined
     (`artifact_quarantined` is true). The test reads only failed.toml, so the property it states is
     stale. `failed-mark-persistence` states the code.
   - `verify::a_check_helper_past_its_limit_is_killed_and_reported_promptly`: "promptly" is never
     asserted (correctly, under the no-latency-budget rule), so the name overstates the test.
3. **Tests that pass vacuously in some environments**
   - `manifest::a_record_the_writer_could_not_read_survives`: the early `return` inside the loop,
     taken when running as root, passes both cases silently, including the one not yet reached.
   - `verify::a_signal_ending_a_bundle_check_helper_is_no_verdict` skips its main assertion
     when the mode-000 premise fails (root) and returns early when trustd is silent.
4. **Timing-dependent tests** (delete once their spec is proved, per AGENTS.md)
   - `checker_supervision_tests::the_holder_writes_the_lock_while_its_checker_is_alive` sleeps 600 ms
     and asserts no write within a 200 ms freshness window for the retired generation. On a loaded
     machine the positive half relies on its 60 s poll. `holder-beat-liveness` is a per-tick contract
     and replaces it.
   - `install_tests::a_foreign_trial_whose_owner_is_still_launching_is_never_disarmed` uses 10 ms
     sleeps to order sentinel mtimes, which breaks on coarse-mtime filesystems.
5. **Source scrapes and prose inside behavioural tests.** These parts are dropped; the specs keep

   - `linux/tests::a_start_that_waited_on_the_lock_rolls_no_healthy_build_back` and
     `linux/tests::whether_the_check_loop_runs_is_asked_without_hashing` assert behaviour only;
     no test in the crate scans a `.rs` file.
   - Many github, install and lib tests also pin wording: "could not finish", "free some space"

## 6. Proof order (easiest high-value first)

No spec is blocked only by gap 0. The order below takes the smallest blocking sets first and,
within a set, the specs that retire the most tests or that later specs cite.

1. **Gap 3 only: scalar arithmetic.** `checker-word-pack-roundtrip` (u64 shifts and masks plus a
   `const fn` enum match; it is the base lemma of the whole checker-watch protocol) and
   `skip-timer-scatter` (one saturating add and a division). Both need only E6 body widening.
2. **Gap 1 only, with near-scalar carriers.** `boot-health-lane` (bool and u32 to a two-arm enum),
   `roster-authority-superseded` (`Option<u64>`) and `lx-check-cooldown` (two string inequalities
   and an i64 compare). These are the first test cases for the enum and `Option` carriers in gap 1.
3. **Gaps {1,3}, with high value.** `jitter-band`, `wake-gap-threshold`, `launch-burst`,
   `checker-phase-classifier`, `failed-mark-backoff-schedule`, `trial-judged-now`, `span-words`

4. **Gaps {2,3}.** `streak-log` and `strand-notice-latch` (gap 2 alone). These are the smallest

## 0. Notation used in the statements

- `Reach(c)`, or `Reach`: the `KeeperCore` states reachable from `KeeperCore::new(c)` by any finite sequence of the public event methods (`accept`, `hello`, `name_marker`, `adopt`, `register`, `meta`, `release`, `bye`, `pending`, `eof`, `peer_exit`, `tick`, `prune_dead_orphans`, `forget_if_passive`), with any arguments, under a `KeeperEnv` whose answers (`holders_of`, `shell_alive`, `pid_alive`, `marker`) are an arbitrary oracle. "k unchanged" means records, peers, pending, settled, brake, relaunch lane and ends are all equal.
- `proc(conn)` = `(peers[conn].pid, peers[conn].birth)`. A peer is *App* when `class = Some(App)`, and *connected* when `eof_at = None` and `exit = None`.
- `Orph(k)`: the rdevs `r` with `records[r].state = Orphaned`, in `BTreeMap` (rdev) order.
- `GRACE` = `DEATH_GRACE_MS`. `Z(s)` = `exited_zero(s)` ⇔ `s & 0x7f = 0 ∧ (s >> 8) & 0xff = 0`.
- *Judged(conn, now)*: `settle` calls `peer_died(conn)`, i.e. the death condition of `core-eof-and-death-condition` holds.
- Wire: `Body(f)` = `f.encode()?[HEADER_LEN..]` and `h_f` = `decode_header(f.encode()?[..8])`. `Bounded(f)`: every length-first part is within its bound (`Hello.build` and `Welcome.version` ≤ `MAX_LABEL` bytes, `marker.dir` ≤ `MAX_MARKER_DIR`, tag ≤ `MAX_TAG`, meta ≤ `MAX_META`, `Status.text` ≤ `MAX_STATUS`). `Complete(f)`: `f` carries every optional trailing field (`Hello.marker = Some`, `Welcome.identity = Some`; vacuous for other kinds).
- Server: `S` ranges over `Server` states reachable by `step()` under any peer behaviour (`test_drop_custody = false`), and `custody(S)` is the rdev → `OwnedFd` map.
- Platform axioms (gap 8; stated, not proved, in a Lean `PlatformSpec`): **P1** Darwin's wait status is `n<<8` for `exit(n)` and `k` for death by signal `k` without a core dump. **P2** a PTY slave's session leader gets SIGHUP exactly when the last master descriptor closes. **P3** the holder scan reads an exited, unreaped process as holding nothing (ESRCH). **P4** an flock is released at process death. **P5** SecCode checks a running process through its on-disk file.
- Model refinements use the Tier-1 runners' event mapping and projections in `src/conformance_custody.rs` (`custody_view(A,B)`, `k_live`, relaunch count; `RelaunchBrake::{streak,held}`; `KeeperCore::last_verdict`).

## 5. Implied specs that look wrong, or disagree with the code

1. **`KeeperCore::release` uses two different notions of "the same process".** The authority check compares claimants by process `(pid, birth)`, but the "others still hold it" check compares by pid only. If one master's two claimants are processes with the same pid and different births (a recycled pid), a RELEASE from one closes the custody copy the other process still claims. When the releasing conn is not a known peer, every other claimant counts as another process. One rule should decide both checks; `core-release-authority` states the code as it is and should be tightened with the fix.
2. **`Frame::decode` mislabels an unknown peer class.** A HELLO with an unknown class byte returns `WireError::Short(Hello)`, although the body is not short. `an_unknown_peer_class_is_refused` only asserts `is_err()`, so it cannot catch this. A distinct variant (e.g. `UnknownClass`) would state it truthfully; `wire-decode-denotation` (class) should then name it.
3. **`code::owner_of` is not the inverse of `copy_name`.** `str::parse::<u32>` accepts `+7` and `007`, so `+7-100-1` and `007-100-1` read as keeper 7's copy, and `sweep` may remove a directory `copy_name` never made. The test samples only names that cannot tell the two apart. Either `owner_of` should require `copy_name(owner_of(s)) = s` (canonical form), or `code-copy-naming` keeps its weaker iff and `code-sweep` inherits the gap.
4. **`job::the_installed_app_and_dev_builds_never_share_a_keeper` asserts something that is not a theorem.** It checks that two distinct dev paths get distinct labels, but the label is a 32-bit fold of FNV-1a-64, so this holds only up to a hash collision. The universal spec (`job-place`) is that a dev place never equals the installed one, plus determinism. Drop the distinct-dev-paths assertion.
5. **`Server::status_text` can panic.** It truncates with `String::truncate(MAX_STATUS)`, which panics when byte `MAX_STATUS` is not a char boundary. The socket path, version and identity description can be non-ASCII. Today the cut lands in the ASCII master lines unless the header lines pass 8190 bytes, but a no-panic proof needs a char-boundary cut (`floor_char_boundary`) or a bound on those fields.
6. **`RelaunchBrake::healthy` resets `streak` but not `held`,** while `manual_launch` resets both. `KeeperCore` always calls `decide` straight after `healthy`, so this is harmless today. On its own, though, the brake API can be held with streak 0, a state `KeeperRelaunchBrake`'s `Healthy` action may not admit. Decide which is meant before proving `refines-relaunch-brake`.
7. **`conformance_custody::the_classifier_judges_real_ends` uses a transliterated oracle.** It computes its expected verdict with the same if-chain as `classify_death`'s body, duplicating `the_classifier_reads_its_table_in_order`. Only the real-wait-status half (axiom P1) adds anything. It also builds its children with `std::process::Command` rather than `aterm_uds::spawnfd::command` (AGENTS.md); module-level allows permit it, and `kernel_custody.rs` does the same.
8. **`src/core.rs::a_slow_booting_crash_loop_is_still_braked` is weaker than the code.** It bounds relaunches at `MAX_STREAK + 1`, but between two brake resets the code grants at most `MAX_STREAK` `RelaunchAt`. `core-relaunch-lane` (f) states the tight bound; the proof replaces the loose assertion.
9. **Three cli tests pin prose.** `start_says_running_only_when_this_builds_keeper_answers`, `stop_says_stopped_only_when_the_keeper_ended` and `status_tells_a_refused_keeper_from_an_absent_one` compare whole output lines with `assert_eq!`, including wording such as "(this label's stop cannot end it)" and `still_running_line`'s text. `cli-start-decision`, `cli-stop-lines` and `cli-status-miss-line` cover only the `key=value` fields and the decisions, so the prose assertions go when those specs replace the tests (AGENTS.md: delete prose-pinning tests).

## 6. Proof order (easiest high-value first)

No spec here is blocked by gap 0 alone: every pure keeper function takes or returns an enum, struct,
`Option`, slice or `String` (gap 1), and nearly all branch or call (gap 3). So the order is the fewest
gaps beyond 0, then value.

1. **`classify-death-table`** (gaps 0, 1, 3). Start with its `exited_zero` half, which is pure `i32`
   bitwise arithmetic and needs only gap 3's shifts and `&` (an `omega`/`bv_decide`-class proof). The
   if-chain over a `Copy` struct of an `Option<i32>` and two enums is the smallest non-scalar carrier
   case in the crate. It retires 2 tests and is the callee contract `core-death-routing` and
   `refines-death-judgement` cite.
2. **`wire-header-codec`** (gaps 0, 1, 3). A fixed `[u8; 8]` array, a 13-arm `match` on `u8` literals
   (the seal-150efe4a range-`match` admission is the starting point), big-endian `u16`. It decides
   every frame the keeper admits and is the base of the three wire round-trip specs.
3. **`brake-decide`** (gaps 0, 1, 2, 3). A two-field struct, a const array lookup and one
   `saturating_add`. It needs certified `&mut self` (gap 2), but it is the smallest `&mut self` in the
   crate, and it makes `refines-relaunch-brake` a short corollary once gap 10 lands. Settle §5.6 first.
4. The string leaves, all gaps 0, 1, 3: **`cli-label-is-ours`**, **`job-own-bundle`**,
   **`cli-status-miss-line`**, **`cli-start-decision`**. They are first users of the `&str`/`Path`
   carriers gap 1 adds. Then **`client-check-error-mapping`** and the pure half of
   **`client-served-policy`** and **`server-holder-verdict`** (`Env::verdict`).
5. **`wire-encode-bounds`** → **`wire-frame-roundtrip`** → **`wire-decode-denotation`** (gaps 4, 5, 7 added).
6. The `KeeperCore` contracts in the dependency order of §1, then the three refinements (gap 10).
7. The effect-lane specs (gap 8): `frameio-roundtrip`, the `server-*` specs, `read-marker-evidence`,
   `link-worker-delivery`, `identity-*`, `code-sweep`, `copy-tree-faithful`,
   `keeper-runs-from-own-copy`, with their platform axioms P1–P5 stated in a `PlatformSpec`.

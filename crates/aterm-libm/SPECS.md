## 0. Notation used in the statements

- `F` ranges over `{f64, f32}`. `bits(x)` = `x.to_bits()`. `sign(x)` = the sign bit of `x`.
- `IEEE_op` names the IEEE-754-2019 correctly rounded operation in round-to-nearest-even:
  `roundToIntegralTowardNegative` (floor), `...TowardPositive` (ceil), `...TiesToAway` (round),
  `...TowardZero` (trunc), `...TiesToEven` (rint), `abs`, `copySign`, `squareRoot`,
  `fusedMultiplyAdd`.
- `NaN-eq(a, b)` := `(isNaN a ∧ isNaN b) ∨ bits(a) = bits(b)`. The NaN payload and NaN sign are
  not specified.
- `FORWARD`: the 31 `f64`/`f32` pairs generated by the `forward!` macro, plus `sincos`/`sincosf`.
  Each body is `F::<std method>(args)` and adds no computation.
- std's float methods lower to LLVM intrinsics or to platform libm calls. Every spec except
  `libm-fdim` and part (a) of `libm-atanh-odd-and-boundaries` therefore needs an IEEE float semantic
  model for the intrinsics, or the FFI assumption channel for the platform libm.
- **Float gap.** Float reasoning has no row of its own in the audit's §7 table
  (`docs/AUDIT-trust-for-test-migration-2026-10-15.md`), and the plan says floats are refused today.
  The gap numbers in §1 are the nearest rows: 1 (carriers: `f64`/`f32`, and the tuple from
  `sincos`), 3 (E6 body: calls, comparisons and branches on floats), 4 (composing a callee's
  `ensures` into the caller) and 8 (FFI assumption channel for the platform libm). Gap 0 (the
  installed seal) is a prerequisite for every row and is listed on each. The missing float row
  should be added to the audit; until then it is the real first blocker for this crate.
- The ulp tolerance of the transcendentals is a property of the host libm. It is not a property
  of this crate's compiled Rust, so it is not a spec here.

## 5. Implied specs that look wrong, or disagree with the code

1. **Stale count.** The `ULPS` doc comment in `tests/recorded.rs` says "95 of the 2,762 rows
   differ". The recorded TSV holds 2,806 data rows (1,778 of them for non-EXACT functions), so 2,762
   matches neither count. Either the fixture grew after the measurement or the number is stale.
2. **Fragile f32 detection.** `tests/recorded.rs::agrees` decides that a row is `f32` from
   `name.ends_with('f')`. That holds for today's 68 names. A future `f64` name ending in `f`
   (upstream has `erf` and `modf`) would silently compare truncated 32-bit patterns. This is a
   test-helper fragility, not a production defect.
3. **Unmarked platform assumption.** Per `lib.rs`, the ulp tolerance was measured on
   aarch64-apple-darwin only. On other cells it is an unvalidated assumption, and the test carries no
   cfg or marker for it.
4. **fdim doc understates the NaN arm.** The `fdim`/`fdimf` summary line in `src/lib.rs` says
   "`x - y` when `x > y`, else `+0.0`". The code returns `x - y`, which is NaN, whenever either operand
   is NaN, because `x <= y` is then false. The doc's second paragraph says so, and the code agrees
   with the recording, but the summary line alone is wrong for NaN. `libm-fdim` states the code's
   behaviour; fix the summary line to match it.

## 6. Proof order (easiest high-value first)

No spec here is blocked only by gap 0: every one needs floats as carriers, which no §7 row
provides yet.

1. **`libm-fdim`**. Blocked by 0, 1 and 3 only. It is pure Rust: one comparison, one branch, one
   subtraction, no calls. It is the smallest test case for float carriers in Trust, and it pins
   down the NaN arm that the doc summary gets wrong (§5.4).
2. **`libm-exact-ieee`**. It adds gap 4 and an intrinsic model. It is high value: 18 functions and
   the whole bit-exact half of the differential, and it gives the abs/copysign lemmas that step 3
   uses.
3. **Part (a) of `libm-atanh-odd-and-boundaries`** (oddness and sign structure). It follows from the
   body plus step 2's abs/copysign semantics, with no platform assumption.
4. **Parts (b)–(d) of atanh, and `libm-forward-refines-std`**. Both need gap 8: an assumed contract
   for std's transcendentals, which reach the platform libm. Once the call is admitted, the
   refinement is a one-line identity per function. Its value is that it states the facade adds no
   computation. After it is proved, delete the atanh test and move the remaining differential to the
   bench (§4).
